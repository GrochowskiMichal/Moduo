## Scope

Tasks v3 makes the Tasks module **complete for students, developers, PMs, founders and small teams, freelancers and agencies, creators, and founder-led sales** — complete meaning each role can run a normal week without opening Todoist, Linear, Jira/Trello/Asana or their small-team tool (47, 50) — and makes it the **UI north star** every later module copies (§5 of the re-plan; rules 38–46a). It was re-planned top-down because v2 was planned bottom-up from a dogfood review and kept paying for solo-planner assumptions stored as columns (re-plan §1.1).

It delivers, in one spec:
- **Structure:** Inbox (personal) · optional Areas → Projects (with description, status, start/target, colour, client, optional lead) → optional Sections → Tasks → Subtasks (one level); handles `MOD-142`; one assignee plus an optional Team; the Waiting on… field (13–20a, 54).
- **Statuses:** per-project names inside five fixed categories, Backlog · To do · In progress · Done · Won't do, with icons per category (53a, 53b); a quiet late state (23); reminders (24); several work sessions per task (25); recurrence as one task that comes back, method a–i (27); a completion record (77).
- **Views:** List with Standard/Detailed rows, Board with per-project columns and one level of lanes, the rebuilt Timeline (projects as bars, tasks as points), Focus (the renamed Queue, with the Now card, Up next, timer modes and subtasks that open in the panel), Upcoming, My tasks, All, the detail panel and the full-page task, one capture for the whole app (61–71, 82–95, 90b).
- **The platform underneath:** every create and edit through a server op with search registration and handles; one shared task store per workspace with delta sync, a device cache and virtualized lists (the 10,000-task target, 37/§6); server-side recurrence; the References primitive (chips, cards, previews) that absorbs the `@ # /` grammar (55, GR-0); the notification table (80); Time & region (76); reminder channels (73); the time report (75); templates and "Duplicate project…" (9, 79); agents as delegates with private session lines (6, 7, 51, 52, 74).
- **The six paused PRs**, reconciled (97–98, group L).

**Why now:** every further change to the task table before the planned cleanup adds another compatibility shim; the re-plan decides every reversal that touches the schema so TV-D7 becomes one cleanup instead of three (§1.1, §6.9). Tasks code and sessions are paused until this spec is ready (2026-10-09).

**Landing rule:** task branches off `maciej`; merge personal → `develop` per AGENTS.md once a chunk lands. Prod migrations wait for a release train (decisions/workflow.md, 2026-10-09) unless Maciej says otherwise for a block.

**Not restated here:** the module's job-to-be-done and depth ceiling (BRIEF), the interaction kit (DESIGN_BRIEF, DS-1–4), the attachment pipeline (`specs/attachments.md`), the shared state layer (`specs/design-state-layer.md`).

## Product behavior & UX

Element-level detail (sizes, exact words, per-state tables) lives in the round-2 research files; each subsection names its file. What follows is the behaviour two people would build the same way.

### 1. Structure (13–20a, 54)

- **Inbox** is personal: the tray for ⌘⇧K captures, email → task and agent captures. "Only you see your Inbox. File a task into a project or assign it, and it moves." Assigning an unfiled task asks for a project in the same picker ("Assign to Mike · in [Bugs ▾]"); "Keep unfiled" moves it to Mike's Inbox and the creator keeps sight of it through "Created by me". The Inbox never appears in project lists, board columns, timeline rows or MCP's project list.
- **Areas** (optional) group projects in the sidebar: name, colour, order; no permissions, no page, no tasks inside. Today's rail sections (`group_label`) become areas in rail order.
- **Projects** (today's `buckets`, same ids, shares and tasks): description, status Active · On hold · Done, optional start and a target date, colour, area, client link, optional Lead (hidden until set), sections. Computed: progress, time, files, waiting, recent activity, "Done this month · 14 · 22h". On hold and Done change only the overview, a dimmed sidebar row and MCP; they never hide tasks. Archive hides a project. Privacy stays on the project (today's Share menu).
- **Sections** (optional, ordered) are the parts of a project — phases, weeks, sprints, milestones, topics — never stages of work (those are statuses). A section carries either a date range or an end date only. The UI only ever says "section"; "column" is never a noun (22a).
- **Tasks** have: title, description (folds after ~8 lines, 56), handle `MOD-142` (workspace key + permanent number; shown in Detailed rows and the panel, searchable, copyable), status, one assignee, optional team, Waiting on… (a list of people or things with "since"), due date (date; optional due time), scheduled sessions (several calendar blocks, 25), reminder, estimate, tracked time, priority (no Urgent), energy (off on rows by default), tags, repeat rule, dependencies, links, files, comments, activity, completion record.
- **Subtasks** are full tasks, one level. Moving a parent moves its subtasks. Finishing a parent finishes its open subtasks, with one Undo naming them (87).
- **Teams** route work: a task gets an optional team next to its assignee; members see "For Design · 2 unclaimed" on top of My tasks and take one with a click; `@Design` in capture routes it; a routed task needs a project (a team can name a default project, else capture asks, 94). Team marks are rounded squares with two automatic letters and a stable colour; people stay round (95). Mentioning a team in a comment sends one notice per member.

### 2. Statuses, dates, repeats (21, 23–27, 53a, 53b, 68b, 77)

- **Categories** Backlog · To do · In progress · Done · Won't do are fixed and carry the app's behaviour; **each project names its own statuses inside them** (rename, add, hide, reorder; each belongs to one category). New projects start from the workspace default (Settings → Tasks → Statuses); templates and "Duplicate project…" carry statuses. Icons belong to the category only: dotted circle · empty circle · half-filled circle · check · crossed circle; nobody edits them.
  - Finishing in Focus, a finished repeat and an agent's "complete" set the project's first Done status; a repeat comes back in its first To do status; moving a task to another project keeps its status name if that project has it, else the first status of the same category; cross-project boards group by category and show the project's own name on the card; filters offer categories everywhere and names inside one project; MCP reads and writes either.
  - **Backlog** tasks keep everything but sit out of counts, My tasks (except a folded "Backlog · n" line), Upcoming, Focus suggestions, drift, late and reminders; queuing or scheduling one moves it to To do; assigning it or giving it a due date offers "Move to To do?". Boards fold Backlog to a small button (icon · count · chevron, stacked, no text, 53b); lists end with a quiet "Backlog · 6" line.
  - **Won't do** replaces task archiving; a reachable list with Reopen. "Archive" stays for projects only.
- **Late**: a passed due date is a muted state, grouped under Earlier, never red, always with a fix on hover or selection: Move · Won't do · Break down. "Rescheduled N×" is gone.
- **Reminders**: "Remind me at…" plus 1 day / 1 hour before due; one precise notice, exempt from digests; delivered by the desktop app (which keeps running in the menu bar when its window closes) and by opt-in browser notifications (73). No email, no calendar feed.
- **Sessions**: a task can be scheduled into several calendar blocks; the estimate no longer doubles as block length; a block's planned length is never recorded as worked time (default r).
- **Repeats** stay one task that comes back, with a–i: RRULE presets and custom rules, repeat-after-completion, due and scheduled move together, a completion history per cycle (who, when; each person sees only their own time), subtasks reset per cycle, future occurrences as faint ghosts on the Calendar and the next one in Upcoming, "move just this one / change the pattern", server-side roll-over, and a picker with one plain summary line. Capture understands the same phrases.
- **Completion** is recorded (when, by whom, per cycle) and drives Filter/Group by Completed (today · this week · last week · this month · range), the project overview's "Done this month", the time report and the seeded "Done last week" view.
- **Dependencies**: one store; a "blocks" link always blocks; a task due before something it waits on is shown quietly (backwards arrow in the late tone, "Waits on X, due after this", one-click "Move to Nov 8"), never prevented; loops are refused (68b).

### 3. Sidebar and navigation (29–30, 29a–e, 98)

Inbox · Focus · Upcoming · My tasks, one hairline, then All · Pinned · Views · areas and their projects (colour dot · name · open count). No labels on the blocks; the you/everyone split is taught in Tasks' welcome. No glyphs on views. Every group collapses (remembered per person), one sentence-case header style, headers only when a group has something, so a fresh workspace shows Inbox · Focus · Upcoming · My tasks · the hairline · All · projects. Customize sidebar (⋯) hides Focus, Upcoming, My tasks or All; Pin adds a project or view to Pinned (which exists only once something is pinned). Archived projects and Recently deleted open from the sidebar ⋯, never as permanent rows. Tasks opens where you left it; the first open follows onboarding.

### 4. List (TV-U1 anatomy kept; 82b, 83, defaults h–n) — [`research/views-list-upcoming.md`](../.design/tasks-v3/research/views-list-upcoming.md)

- **Rows**: two presets, Display → Rows: Standard · Detailed, remembered per view (developers start on Detailed). Standard: status icon · title · quiet counts (tags · files · comments · n/m · blocked · waiting · repeat · "Claude · working" where visible) · project when not implied · priority · date · avatar · Focus mark (on hover, always once added). Detailed adds handle, "Project › Section", the status name, Due and Next session as two columns, estimate/time, waiting on, assignee name, updated, with sortable column headers. Titles give way first; the date column sizes to its widest value; nothing truncates.
- Click the status icon to complete; ⇧S opens the status menu; `>` / `<` nest and un-nest. Hover shows only the Focus mark, a date picker in an empty date cell and the late fixes.
- **Grouping**: Section (default inside a project) · Status · Priority · Assignee · Team · Date · Project; never Tag or Energy. Sticky sentence-case headers with a count and a "+" that stays visible and adds at the top with the group's value filled in; collapse remembered. Each group ends with "3 completed · show" and, where relevant, "Backlog · 6".
- **Date grouping** everywhere is Earlier · Today · Tomorrow · the next five day names · Later (+ No date outside Upcoming); "This week" is a filter, not a group (83).
- **Ordering**: manual drag order lives inside one project (and its sections); sorting shows "Sorted by due · Back to manual order"; dragging while sorted asks to switch back; cross-project views only sort.
- **Multi-select** (⇧-click, ⌘-click, ⇧↑↓): the bottom bar's centre shows Complete `Space` · Focus `Q` · Assign `@` · Tag `#` · Date `D` · Delete `⌫` · More ▾ · "4 selected · Esc" (82b); the right panel shows "4 tasks" with shared values and "Mixed"; one Undo per change.
- **Filter and search**: the FilterBar chip grammar (DS-4), search within the view, ⌘K across everything (server-side); saved views live only in the sidebar's Views group (29d).

### 5. Board (22, 22a, 53b, 85–87, defaults n–o) — [`research/views-board-detail.md`](../.design/tasks-v3/research/views-board-detail.md)

Boards always open grouped by Status (86); Section, Assignee, Team, Priority, Waiting, Project/Area (across projects) are one Display choice away and remembered per project. One project's status board gets "+ Add status"; a section board "+ Add section"; other groupings have no add button. Cards: one Card at a fixed width per density (296 / 280 / 264 px); Standard shows status icon · title · one meta line; Detailed adds the handle and a second meta line; no description unless Display → "Description preview". Status, section and priority columns always show; assignee/team/project/waiting columns hide when empty with "3 hidden". Drag between columns changes the field; inside a column reorders (one project only). Lanes (Display → Lanes: none · assignee · priority · project · team) are one level, off by default, each foldable, empty lanes hidden. Each column scrolls and virtualizes on its own. One context menu for rows, cards and bars.

### 6. Timeline (67–71, 68a, 68b, 46a) — [`research/timeline-competitors.md`](../.design/tasks-v3/research/timeline-competitors.md)

- **Rows by scope**: All/area → area headers, then one row per project (bar start → target, solid when set, outlined when worked out from its tasks; sections as segments; progress underline; expand ▸ to its tasks by section); opens at Quarter. Inside a project → the project row, its sections (range = a band behind its rows; end date only = a diamond on the section's row) and its tasks; opens at Month. My tasks/Upcoming/views → tasks by project (or assignee). Subtasks hidden by default. Optional "Due per week" count in the header (on by default for students).
- **Tasks are points**: a 12 px circle on the due day; a hollow circle on the next session when only sessions exist; muted late tone when overdue; done hidden unless Show done. No task bars, no fades. Words: tasks are *due*, sections *end*, projects have a *target*.
- **Anatomy**: a sticky, resizable name column (280 px default; ⇧[ hides it), rows 36/32/28 px, project bars 24/22/20 px, two-tier sticky time header with a Today pill, hairline grid stronger at months, faint weekend tint at Week/Month, zoom Week · Month · Quarter · Year (⌘-scroll), endless virtualized scroll opening with today a quarter across, sentence-case group headers, no rotated text.
- **Interactions**: drag a point (due), a diamond (section end), a bar (project; ends resize); click an empty spot to set a due date or draw a project bar; the whole canvas takes drops; multi-move; edge auto-scroll; Undo on every change; keyboard ↑↓, ⌥←/→ a day (⇧ a week), D picker, T today, Space/Enter; dependency lines only for the selected/hovered item plus "Show all"; moving a task offers "Also move the 3 that wait on this". "No date · 6" opens the panel's No date view; the bottom tray is gone.
- **Display**: Group by · Show done · Show undated · Colour by · Dependencies · Show sessions · Show repeats · Subtasks · Due per week. Left out by design: baselines, critical path, auto-scheduling, workload lanes, hidden weekends, red health, task start dates.

### 7. Focus (31, 61–66, 62a, 63, 65a, 57, 59a, 10) — [`research/focus-competitors.md`](../.design/tasks-v3/research/focus-competitors.md), prototypes round-2a frames 1–3

- **Name and shape**: the sidebar view is **Focus**; the line-up inside is **Up next**; verbs are Start · Pause · Done · Stop. `Q` adds a task to Focus; ⇧F "Focus on this" puts it on top and starts; the Calendar's ▶ on a block does the same.
- **Screen**: header "Focus ⋯" only. The **Now card**: one quiet line (project › section · due, priority mark only when high) · one timer pill top-right · title · description (folded) · references as chips · subtasks as an unordered checklist with small marks ("notes · 1 file") · Done ⏎ · Skip · Hand off W. **Up next · 4 · ~1h** with project dividers, "Arrange by project · 2 fewer switches" when it saves ≥2 switches (undoable), and a meeting divider ("2:30 PM · Acme call") where an event within ~2 h falls. Bottom: "2 done · 1h 12m · Show".
- **Timer** (Settings → Tasks → Focus and the ⋯ menu): Per task (default; the pill on the card, "+5m" neutral overrun, optional countdown of the estimate) · Pomodoro (one rhythm pill in the header beside ⋯, breaks offered between tasks, time still recorded per task) · Off (no pill, nothing recorded). Leaving the view never stops a session; it shows in the top bar (96). Stop lives in ⋯ (and the top-bar timer), far from Pause, with "Stopped · Undo" for 10 s; a session ends by itself when Up next runs out.
- **⋯ menu**: Timer ▸ · Arrange by project · Offer quick tasks along the way ✓ · Show what's done this session · ─ · Stop.
- **Subtasks**: clicking one opens *its own* details in the right panel (description, files, links, comments, parent breadcrumb, "Focus on this ⇧F"); the card never repeats; ⏎ is Done for the focused task (65a).
- **Between tasks**: with the switch on, at a project change one offer appears in place of the next card: "Before you leave Acme: Send invoice #14 · 5m — Take it ⏎ · Not now Esc" (≤15 min tasks, once per change, three Not-nows → Shrink · Move · Let go).
- **Three ways in**, taught by the empty state: Q on several tasks; ⇧F on one big task; "Line up today's 3 scheduled tasks" shown as real rows with "+" each.
- **Usual pace**: after ~10 timed tasks, "≈ 7h 30m at your usual pace" in Up next's header and the session summary; personal, off-able.
- **In flight** (hand-offs with check-backs) is the panel's second view; the card brightens when a check-back is due, with one quiet notice. **Agent work** shows as status, not conversation: "Claude · working" on rows, one line on the task ("Claude · Writing tests · step 3 of 5 · 2 min ago · PR #42 ↗") with earlier notes folded; private to whoever started it unless "Show my agent work to teammates" is on; the trail always says "Alex · via Claude Desktop" (51, 52).

### 8. Upcoming, Inbox, My tasks, All (29, 83, 84, defaults h, r–t)

- **Upcoming**: one row per task at its next session or due date, whichever is first; missed sessions in Earlier as "missed 2:00 PM"; passed due as late; day headers "Thu · Oct 15 · 3 · ~2h 30m"; no week strip; drag between days reschedules; covers your dated tasks plus unassigned ones in projects you can see, minus tasks routed to a team you're not in.
- **Inbox**: newest on top, manual drag; source chips for email- and agent-captured tasks; triage keys 1 accept (file + assign to me) · 2 decline (hand back with a note; Won't do if mine) · 3 duplicate of… (merge comments and links, then Won't do) · H snooze until a date; a calm zero state.
- **My tasks**: the team block first, then by status (In progress · To do · Backlog folded); date grouping one Display choice away.
- **All**: grouped by project within areas; the Board across projects groups by category.
- **States for every view**: first run teaches one gesture; loading shows a skeleton, never "Nothing here yet"; filtered to nothing says "No tasks match · Clear filters"; read-only hides edit affordances; offline opens read-only from the device copy with captures and check-offs queued ("2 waiting to sync"); 10k tasks virtualize with sticky headers.

### 9. Detail panel and the full page (32, 56, 72a, 88, 89, defaults p–q) — [`research/views-board-detail.md`](../.design/tasks-v3/research/views-board-detail.md) §7–12

- The panel is never narrower than 280 px (shell). Title row is the view dropdown "Details ▾" (views: Details · Project / In flight; No date on the Timeline); a reference opened from anywhere shows as "← item name". Order: breadcrumb (project › section) · title · handle · status · always-shown properties (Status, Assignee + Team, Priority, Due, Tags) · "+ Energy · Scheduled · Reminder · Estimate · Repeat · Waiting on" · description folded at ~8 lines with "Show more · 2 tasks · 1 email" (editing shows all; a card is never cut) · subtasks (inline add, reorder, open with back arrow, n/m) · Linked (reference cards) · attachments strip · the agent session line (where visible) · one feed with "All · Comments", comments editable and deletable, six fixed reactions that never notify (👍 ✅ 👀 🙏 ❤️ 😄), no threads. Values wrap instead of truncating; the label column narrows under 320 px.
- Nothing selected inside a project shows the Project view. Pickers: status (the project's names, grouped by category), assignee + team, due vs sessions vs reminder (DateField only), estimate, priority, project › section, waiting on (list), repeat (presets + custom + summary line).
- **Full page** expands the task into the centre on the same route, two columns (properties right); the panel shows Project; anything clicked in the page opens there with a back arrow; the description never folds.
- States: deleted → "Deleted task" tombstone; no permission → "Private item"; loading skeleton; viewer → read-only.

### 10. Capture (33, 33a, 90, 90b, 91–94, defaults g) — [`research/capture-references-teams.md`](../.design/tasks-v3/research/capture-references-teams.md) §1–5, prototype round-2b frame 6

- **Two ways in**: ⌘⇧K from anywhere opens the app's capture as **Task → Inbox** and never asks where; ⌘N, "+ New" and `c` file where you are (project, section, the top of Up next). Inside the modal ⌘1–7 switch the capture's type to the module of that number (Note, Event, Message…); the type chip shows it; ⌘1 does nothing. Tasks ships the shell and the Task type; other modules register theirs when rebuilt.
- **Anatomy**: a type chip and a destination row ("Inbox ▾" / "Acme rebrand › Design ▾"), the title line with live tokens, description (grows to ~6 lines then scrolls), four pills Assign (people and teams) · Due · Tags · Priority · ⋯ More (scheduled, reminder, estimate, repeat, waiting on, template), a removable "From: …" chip when an email, note, event or contact was open (93), subtasks typed inline, attachments by paste or drop, ⏎ Create · ⌘⏎ Create more.
- **The grammar**: `@` mentions people first then things (a person assigns; a team routes; a project files; a contact, note, email, event or task links); `#` applies tags; `/` runs commands (`/today`, `/tomorrow`, `/next week`, `/date`, `/due …`, `/schedule …`, `/remind 4pm`, `/priority high`, `/estimate 2h`, `/repeat …`, `/template …`). Plain date phrases ("tomorrow 3pm", "every Tuesday until Dec 15") are recognised and highlighted in capture only; Esc keeps the words; a date alone sets due, a date with a time schedules. Literal symbols stay text (`C#`, `#123`, `and/or`). `#CS 201` matching a project offers "CS 201 is a project — @CS 201".
- **What leaves the title on save**: tokens that set a property (person, team, project, tag, date, `/` command) move into their pill; tokens that link a thing stay as chips (92). `@person` without a project keeps the task unfiled and shows the empty project slot before ⏎ (20a); `@team` without a project asks for one unless the team has a default (94).
- **Paste** a multi-line list → "Create 12 tasks?"; indented lines become subtasks. Offline captures wait on the device and send when back.

### 11. References, the shared primitive (55, default u, GR-0 folded in) — [`research/capture-references-teams.md`](../.design/tasks-v3/research/capture-references-teams.md) §6–8, prototype round-1c frames 2–4

One way to show a linked item anywhere: **link** (inline text with a type icon), **chip** (pill with one live fact: "○ Collect assets · Fri"; a contact shows avatar · name), **card** (key facts and one action), **hover preview** (the card). Defaults: a chip in running text, a card alone on a line, in chat a chip plus collapsible preview cards. "Show as: Link · Chip · Card" appears after inserting. Live: titles and statuses update in place; a deleted item reads "Deleted task"; an item you can't see reads **"Private item"** with no title and no preview, and never leaks a title into a notification or the trail. Clicking opens it in the right panel as "← item"; ⌘-click opens it full. Previews are lazy and cached. Per-type content (task: status · title · handle · project › section · assignee · due · n/m · waiting, action Complete; email: sender · subject · snippet · date · count · waiting-on-reply; contact: avatar · name · role · company · last contact · open tasks; note: title · excerpt · last edit; event: title · time · people; project: colour · name · status · target · progress) is the table in §6 of that file. The app-wide grammar `@` `#` `/` (prose: `@` links and notifies, `#tag` links, `/` inserts and creates; `/today` and friends insert a date chip) is part of this primitive, which retires GR-0 as a separate spec.

### 12. Agents and MCP (6, 7, 51, 52, 74)

Agents are delegates: through the one Moduo connector they create projects, sections and areas, file and date tasks with repeats and tags, set status by category or name, assign, route to a team, queue, hand off, complete, add a comment only when a person asks, and post the five-field session status (state working · needs you · ready for review · failed; note; optional step n of m; links; times). Imports through your AI keep an "imported from" reference (`ENG-123`), re-run as updates, and ship with "Undo this import". Every agent write is a logged server op attributed "Alex · via <key name>". Sessions are private by default; "Show my agent work to teammates" opens them; the hand-back summary stays private until "Post as comment". Notifications go once, to the person who started the agent, on needs you · ready for review · failed. Tool list: §Assumptions #14.

### 14. Time, reports, Time & region (8, 10, 12, 63, 75, 76)

Tracked time is a log of dated entries (TV-D3); Focus adds a closed stretch per task; "Add time…" in the Time field logs "2h · yesterday · note"; your own entries are listed and editable; a teammate's time reaches the owner's report only with "Share my tracked time with the workspace owner" on. The report opens as a sheet from a project's overview and a client's hub: period · by task or by day · totals · optional 15-minute rounding · Export PDF (one branded, printable layout) · Export CSV. No rates, no invoices. Settings → General → **Time & region**: time zone (device default), week start, 12/24h, date order; a due date is the same date for everyone; times and reminders are moments shown in each viewer's zone; repeats roll over at the assignee's midnight; a travel prompt once when the device zone changes.

### 15. Templates, duplication, import, people and projects going away (9, 35, 74, 78, 79)

- **Task templates**: "Save as template" keeps the work (title, description, subtasks with their details, tags, priority, estimate, dependencies between subtasks, links to lasting things, default project, dates as offsets) and drops the run (comments, activity, time, done states, repeats, email links, files). The template is its own editor (opens as a task marked *Template*; editing never changes tasks made from it). "From template" in capture (`/template`). Yours until shared with the workspace.
- **Project templates and Duplicate project…**: a project template keeps description, sections, statuses and open tasks (with subtasks, descriptions, date offsets), nothing done or tracked; "New project → From template…" asks for a name and a start date; "Duplicate project…" does the same from a live project. Templates live in New project and Settings → Tasks → Templates.
- **Import**: first through your AI (74), then native: Todoist CSV → Trello JSON → Linear/Jira/Asana CSV; old IDs stay findable; Trello lists become statuses with a confirmed category; Todoist/Asana sections become sections; deeper subtasks flatten; task start dates are dropped and the summary says so.
- **A member is removed**: their tasks become unassigned (PRIV-2, live); their Inbox tasks created by others go back to their creators, the rest to the remover; Lead is cleared; teams and views drop them; private projects are handed on first or go to Recently deleted. **A project marked Done or archived with open tasks** asks once: "4 open tasks — Won't do · Move · Keep". Archived projects never remind or repeat and stay searchable, labelled. **Deleting a project** moves only its open tasks to their assignees' Inboxes (unassigned → the deleter's) with one quiet notice each; the rest goes with it to Recently deleted (30 days).

### 16. Onboarding and welcome (34)

One role question per person ("What will you run in Moduo?") sets defaults only: preset, first view, seeded views, three teaching tasks, a starter template. Tasks' welcome shows once per person: step 1 the basics with "Learn more" / "Explore on my own"; up to three steps with a looping clip recorded from the real app: (1) above the line is yours, below it is shared; (2) line things up in Focus and work through them; (3) `@` assigns, files and links · `#` tags · `/` runs commands, the same everywhere. Reopen from ⋯ → "What's in Tasks". No forced steps, no app-wide tours.

### 17. Settings → Tasks

Statuses (workspace default), Templates, Focus (Timer · Offer quick tasks along the way · usual pace on/off), Show my agent work to teammates, Share my tracked time with the workspace owner, Time & region (General), Notifications (the table's switches), Members → Teams (any member creates; creator/owner/admin deletes).

### 18. Calendar, Home and the top bar: the contracts (26, 12, 96, default r, re-plan §4)

- **Calendar** (rebuilt later; Tasks provides): your own due-only tasks as all-day chips (the Month view is Calendar's own block); sessions count as busy for booking links, with a switch per link; your sessions as blocks; future repeat occurrences as faint ghosts; drag from the Calendar's Tasks list to schedule; ▶ on a block = Focus on this; "took longer" is an adjustment, never a planned length; one clock app-wide. Teammates' unassigned tasks stay out.
- **Home**: the Tasks widget shows Focus (Up next), or Open when empty; the time widget reads task time; the team-load widget lists one row per member (queue size and lined-up time, in progress, waiting, due this week; nothing about runs or time per person); Upcoming. Other widgets: their own round.
- **Top bar** (built in its own session): the running Focus timer (quiet "18:02" with a dot; hover pauses, click opens Focus) · Help (Docs, Keyboard shortcuts, Contact support, Report a bug) · bell · avatar. The bottom bar's centre is Search · Quick capture · New; during a multi-select it shows the mode row of 82b.

### 19. The visual rules every module inherits (38–46a, 48b, 81, re-plan §5)

Three readable text levels plus one decorative; hover = fill, one selection tint, one focus ring, one drop target, one drag preview; never capitalise people's words; one sentence-case header style for every grouping (small caps only for fixed chrome); one date/time/duration grammar (Today · Tomorrow · Mon · Oct 16 · Oct 16, 2027 · 3:00 PM · 45m · 1h 30m · 4h) with dates, times and counts never truncated; titles give way first, meta drops whole items behind "+n"; avatars are two initials with a stable colour; density applies to cards, menus, tabs and pills; one chip and one count language; an accent budget selection > today/now > done check > queued; text is never rotated; the 3×3 layout (top bar global · left overview · centre surface · right context · bottom bar module tools and panel toggles) with no rails or extra columns. Motion foundations: fast ~100 ms (hover, press), base ~180 ms (menus, popovers), slow ~280 ms (panels, view switches), ease-out in / quicker ease-in out, four patterns (panel slide-fade, popover grows from its origin, row height+opacity on add/remove, view crossfade), reduced motion → opacity only, no blur.

## Edge cases

Each becomes a test (next sections). Grouped by what fails.

**Statuses and categories**
- A project renames or deletes a status that tasks use → tasks keep their category; deleting a status moves its tasks to the project's first status of that category and says so; a category can never be empty of statuses.
- An old desktop build reads a Backlog task → it sees the category in the legacy status field (To do) and nothing disappears; it cannot write a per-project status name (its write maps to the category's first status).
- A cross-project board with two projects whose status names differ → columns are categories; each card shows its own name. If every project in view uses the same names → columns use the names.
- Moving a task to a project without a matching status name → first status of the same category; the trail records both the project and the status change.
- Agent sends an unknown status name → refused with the project's list; a category word is always accepted.

**Dates, zones, repeats**
- Due date on a task shared across time zones → the same calendar date for everyone; a due *time* shows in each viewer's zone; the "1 hour before" reminder fires relative to the assignee's zone.
- A repeat with due and scheduled set → both move together keeping their gap; one dragged occurrence asks "Move just this one · Change the pattern".
- The app has been closed for a week → the server already rolled repeats forward; nothing reopens the same day; missed occurrences never pile up (the P0 #2 bug cannot recur).
- A task due before the task it waits on → shown, never refused: backwards arrow in the late tone, "Waits on X, due after this", one-click Move. A dependency chain that would loop → refused with a plain message.
- Week start Sunday vs Monday → Upcoming's day names and "Due this week" follow Time & region; Calendar follows the same setting.
- DST change inside a scheduled session → the block keeps its wall-clock start; tracked time counts real seconds.

**Structure moves**
- Moving a parent task → its subtasks move with it; Undo moves all back.
- Deleting a section → its tasks go to "No section" in the same project; nothing is deleted.
- Deleting an area → its projects become area-less; nothing else changes.
- Deleting a project → open tasks to assignees' Inboxes (unassigned → the deleter's) with one notice each; done/won't-do tasks go with the project to Recently deleted; Restore within 30 days brings the batch back, tasks included, and returns moved tasks only if they haven't been edited since.
- Assigning an unfiled Inbox task to someone → the picker asks for a project; "Keep unfiled" moves it to their Inbox; the creator still finds it under "Created by me".
- Dragging a task onto the Inbox sidebar row → nothing happens (a shared task never turns private by a drop).
- A task routed to a team the creator isn't in → allowed; the creator keeps "Created by me" sight; a routed task with no project → capture refuses ⏎ until a project is picked or the team's default fills in.
- A member leaves a team → their claimed team tasks stay assigned to them; unclaimed ones stay with the team.

**Focus**
- Two devices → one session per person; the second device takes over the clock with the first shown as "Running on your laptop · Take over"; time is never double-counted (idempotent saves).
- The app sleeps mid-stretch → the away prompt (Keep · Discard · Count as break) as today; unanswered at session end → discarded.
- Timer Off → no pill, no entries written, usual pace never appears, Up next still works.
- Pomodoro phase ends while away → caught up from timestamps, no work block auto-starts.
- The focused task is completed by a teammate or an agent meanwhile → the card shows "Done by Sam · Next ⏎" and moves on; time already tracked is kept.
- The focused task is deleted or unshared meanwhile → "gone": the seconds are dropped with a note, the card moves on.
- Stop pressed by accident → "Stopped · Undo" for 10 s restores the session with its clock.
- Up next empties mid-session → the session ends itself with the summary; the along-the-way offer never shows with nothing left.
- A subtask opened in the panel is finished there → the card's checklist updates; finishing the last open subtask does not finish the parent by itself (the parent's Done does).

**Capture and references**
- `@tom` with both Tom and a project "Tomorrow" → people first; `/tomorrow` is the date; nothing auto-converts prose.
- Paste "C# tips" or "#123" → literal text.
- A date phrase the user wants as words ("Prepare Monday notes") → Esc on the highlight keeps it as text; renaming an existing task never parses dates.
- Offline ⌘⇧K → the capture is kept on the device, shown as "waiting to sync", sent on reconnect with the same id (no duplicate).
- A reference to an item the reader can't see → "Private item", no title, no preview, not in their notifications or trail; the author still sees it normally.
- A referenced item is deleted → "Deleted task"/"Deleted note" tombstone, no preview; restored → live again.
- The "From:" chip on a ⌘⇧K capture is removed → no link is created; removing it after save removes the link.
- A multi-line paste of 300 lines → "Create 300 tasks?" with a cap at 500 and one Undo for the batch.

**Lists, boards, bulk, order**
- Sorting while a manual order exists → "Sorted by due · Back to manual order"; dragging while sorted asks first; the manual order is kept untouched underneath.
- Bulk action on 4 tasks where one is read-only to you → the three change, the fourth is named in the toast, one Undo for the three.
- Bulk Date on tasks with repeats → offers "Move just these occurrences · Change the patterns"; default the occurrences.
- A board column with 500 cards → virtualized, scrolls on its own, drag still works across columns.
- Finishing a parent with open subtasks → all finish, toast "Done · also 2 subtasks · Undo".
- Group header "+" in a Status group of a cross-project board → disabled with "Pick a project first" (no single project to add to).

**Views, scale, offline, permissions**
- 10,000 tasks in a workspace → open tasks load first; List, Board, Timeline and Upcoming draw only what's on screen; opening a task, searching and switching views stay under 200 ms on the CI fixture.
- First sign-in on a new device → a few seconds of initial sync with a skeleton; thereafter opens from the device copy, then delta-syncs.
- Network drops → read-only from the device copy; captures and check-offs queue; other edits say "Offline"; reconnect runs a delta sync and flushes the queue in order.
- A viewer (read-only member) → no checkboxes, drag, add or bulk; references still open; Focus can line up their own tasks only if they can edit them (a viewer cannot).
- A deep link to a task assigned to you inside a project you can't see → the task opens; its project shows as "Private project" (never "Inbox"). A deep link to a task you can't see at all → "Private item" with a way back.
- A write fails on the server (permission or validation) → that one field rolls back with a toast; nothing reloads.
- Realtime echo of your own pending write → skipped; a teammate's newer write to the same field → wins and is shown; Undo never overwrites a teammate's later change (it says so).

**Templates, imports, people**
- Saving a template from a private project → stays yours; sharing it with the workspace asks "This includes 12 tasks from a private project. Share?".
- Duplicating a project with sections that have dates → all dates shift from the chosen start; statuses copy; done tasks don't.
- An AI import run twice → the second run updates by "imported from" key, creates nothing new, and "Undo this import" removes exactly the first run's rows that weren't edited since.
- A member is removed → PRIV-2 rules plus §15: nothing is orphaned; Lead cleared; their private projects handed on or trashed.
- A project marked Done with open tasks → one prompt: Won't do · Move · Keep; Keep leaves them open and visible.

**Notifications and reminders**
- Twelve tasks assigned at once → one notice.
- A reminder on a task later moved to Backlog or Won't do → the reminder is cancelled; moving it back to To do asks whether to restore it.
- The desktop window is closed → the app keeps running in the menu bar and reminders arrive; quitting the app shows "Reminders won't arrive while Moduo is quit" once.
- Browser notifications not permitted → the bell still shows the reminder; the setting shows "Not allowed by the browser".
- A team mention in a comment by a member of that team → everyone else in the team hears once; the author doesn't.

**Agents**
- An agent reports "working" then goes silent → "No update for 40m" computed after 30 minutes, no notification.
- An agent's key is revoked mid-session → the session line reads "Stopped (key revoked)"; the trail keeps "via <key name>".
- "Show my agent work to teammates" switched off mid-session → teammates stop seeing the line at once; the trail stays.
- An agent tries to hard-delete, re-own a project or write outside its scopes → refused by the op; nothing partial is written.

## Assumptions & technical decisions

Decided by the agent (re-plan §6 and round 2); each line is decision · why · rejected. Durable ones are entries in `docs/decisions/tasks.md`.

1. **Every create and every field edit is a server op** (`tasks_op_create`, `tasks_op_update(field…)`), from the UI, ⌘⇧K, MCP, import and templates; the op registers the entity (and re-registers on rename), assigns the handle, logs activity, and is the only write path once TV-D7 revokes raw grants. *Why:* fixes search, gives agents capture, makes handles possible, one attribution path. *Rejected:* keeping single-field raw writes (the contract's "for now" clause) — it is exactly what left tasks unregistered.
2. **Handles** = `workspaces.task_key` (2–5 uppercase letters; default from the workspace name; an owner edits it once in Settings → Workspace → Task key) + `tasks.number` (per-workspace sequence, never reused, assigned in the op; until D7 a BEFORE INSERT trigger also numbers and registers rows inserted raw by old builds). *Rejected:* global ids (cold, long) and per-project keys (renumber on move).
3. **Statuses** = `project_statuses(id, project_id, category, name, position, hidden)`; `tasks.status_id`; the legacy `tasks.status` column becomes a mirror of the category maintained by trigger until TV-D7, and a legacy write of it maps to the category's first status. Default sets are `project_statuses` rows with `project_id IS NULL` (#28). The vocabulary `TASK_STATUS_CATEGORIES` in `@contracts/vocabularies` replaces `TASK_STATUSES` at D7 (`archived` → `wont_do`, plus `backlog`). *Rejected:* free-form statuses (behaviour would have to be configured per name); a global custom list (projects differ).
4. **Dates:** a new `tasks.due_on date` plus optional `due_time time`; the old `due_date timestamptz` stays until D7, mirrored both ways by trigger (new writes set `due_date` to noon UTC of `due_on`; an old build's timestamp write sets `due_on` from the writer's zone), so old builds never land a day off. `scheduled_at` is superseded by `task_sessions(id, workspace_id, task_id, user_id, starts_at, ends_at, updated_at, deleted_at)`; until D7 `scheduled_at` and `duration_minutes` are mirrored from the next session, and an old build's write of them upserts the first session. Reminders are `task_reminders(id, workspace_id, task_id, user_id, at, kind, updated_at, deleted_at)` with a pg_cron sender. All moments are `timestamptz`, dates are dates. `tasks_with_drift` (`t.*`) is dropped before any column drop (D7). *Why:* off-by-one across zones, and sessions need their own rows. *Rejected:* changing `due_date`'s type in place (breaks old builds and the view); a third "start date" (68a).
5. **Recurrence on the server:** a pure SQL/plpgsql occurrence function for the supported RRULE subset (daily/weekly/monthly-by-day/nth-weekday/yearly, interval, until/count, workdays) plus "after completion"; the pointer moves only in `tasks_op_set_status` and the pg_cron roll-over; completion history in `task_completions(id, workspace_id, task_id, user_id, completed_at, cycle_key)`. Roll-over happens at the assignee's midnight using `user_preferences.time_zone`, which D8 starts writing from the device at every sign-in (Time & region in D14 only adds the Settings UI and the override). The client engine stays for previews only. *Rejected:* keeping client catch-up (the reopen bug).
6. **One dependency store:** `task_relations` is canonical; a hub/MCP "blocks" link writes a relation; cycles refused by the existing trigger; reads and writes follow the access checks PERM-W lands.
7. **The shared store** (`src/lib/sync/`): one per workspace, IndexedDB (Dexie) cache keyed by workspace, delta sync by `updated_at > last_seen` per table (tasks, buckets/projects, sections, areas, statuses, sessions, queue, tag_links, comments counts, relations, teams), Realtime applied by `updated_at` with echo-skip by op id (from TV-D5), open tasks first and done/won't-do/backlog lazily, server-side search (`tasks_search` RPC), writes through ops with one-field rollback, an offline queue for captures and check-offs. *Rejected:* a generic ORM/sync framework (one more runtime), and per-screen refetch (the thing being replaced).
8. **Virtualization:** TanStack Virtual for lists, each board column, timeline rows and the timeline's horizontal range; rows memoised by task id; hooks with stable identities. **Perf gate:** `tests/perf/tasks-10k.spec.ts` on a generated 10,000-task fixture, in CI, budget 200 ms for open-task, search and view switch.
9. **Minimum client build:** `app_settings.min_build` (a two-column table created by D8) checked at boot; below it the app shows "Update Moduo" and runs read-only; the client tolerates unknown vocabulary values by rendering the category and never dropping rows (§6.3, §6.7).
10. **Manual order** lives on `tasks.position` scoped to (project, section); cross-project views sort only; a Board reorder in Focus is disabled (§6.8).
11. **One time engine** (`features/focus/engine`): Focus, Calendar block focus, the Home pomodoro and the top-bar timer share it; saves go through `tasks_op_track_time` from any page; `focus_runs.mode` is `per_task | pomodoro | off` (the #323 migration re-cut, 62a); time entries per task also in Pomodoro mode.
12. **Projects, areas, sections, teams, waiting:** `buckets` keeps its name until D7 (API aliases kept); #328's migration (`20261009140000_buckets_archive_trash`, landed by TV-U6) adds `color` and `archived_at`, and D10 adds `status, starts_on, target_on, lead_id, client_contact_id, area_id`; `group_label` stays mirrored from the area's name until D7; `task_time_blocks` rows move into each person's `user_preferences` at D10 and the table is dropped at D7; `areas(id, workspace_id, name, color, position)`; `sections(id, project_id, name, position, starts_on, ends_on)`; `tasks.section_id`; `teams(id, workspace_id, name, mark, color, default_project_id)`, `team_members`, `tasks.team_id`; `task_waiting(task_id, kind person|email|agent|text, ref, since)`. Areas carry no permissions; sections inherit the project's. *Rejected:* areas as containers with permissions (candidate B) and tasks on several lists (C).
