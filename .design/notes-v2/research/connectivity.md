## 0. Headline

1. **Notes is already a citizen of three of Tasks v3's contracts, by adapter, not by design.** SH-1 registered its old tabs as panel views and its one-line capture as a provisional type; RF-1 grew Notes' `entity-ref` node into the Reference node in place; TV-U14's "From:" chip already reads the open note. Everything else (the `@ # /` grammar, the shared store, the panel stack, the date grammar, the kit, notifications, MCP v3, templates) Notes does its own way or not at all.
2. **The cheapest wins are client-only and local to Notes:** one `/` menu instead of two (§1 row 4), task lines reading categories / `due_on` / sessions (row 5), a real "← item" stack (row 1), the Note capture body (row 2), the app date grammar (row 9). None needs a migration.
3. **The expensive piece is data:** note metadata joining the shared store needs a thin change feed, a meta stamp and a grants-feed widening (§2); an agent write path that edits the CRDT (row 10) needs a spike; copying prepared notes for the hackathon needs a Notes half of TV-D15's copy engine (row 14).
4. **Two corrections to the brief.** (a) The note chip is *defined*: research [`capture-references-teams.md:181,188`](../../tasks-v3/research/capture-references-teams.md) reads call 55's "—" as "icon · title" for both link and chip, and the card as "Title / 2-line excerpt / *Edited by Sam · Oct 8*". What's missing is the server half: `notes` has no last-editor column, so today's card says "Edited Oct 8" without the who (`resolvers.ts:187-206`). (b) TV-U13, TV-D12, TV-D13, TV-D14, TV-D15, TV-U12, TV-U17 are **landed on origin**, not "in progress" (REPLAN §7's table is stale; §3 here is current).
5. **Chat-1 (reactions widen app-wide)** costs Notes nothing in schema: origin's `comment_reactions` is keyed by comment and its item gate already has a `note` branch. It costs TV-U13 a re-cut (a closed six-word vocabulary becomes open), owned by Chat's block (row 7).

## 4. Risks

1. **TV-D7 breaks task lines** unless Notes' task-line re-cut (row 5) lands before it; nothing in TV-D7's notes mentions Notes.
2. **Agent edits lose data today** (row 10): any MCP append/update to an existing note is overwritten by the next keystroke. Until the CRDT path exists, `notes_append` / `notes_update` should refuse notes that have a doc rather than half-work.
3. **Hackathon copies need id remapping across modules** (row 14): a prepared page with task lines pointing at prepared milestones only stays connected if TV-D15's apply returns a source→copy map. Ask the hackathon plan before Notes' block is cut.
4. **Body pushes bump `updated_at`** (§2): any metadata delta or Realtime design keyed on it churns per keystroke; the meta stamp must land with the store work.
5. **Two link directions for `spawned-from`** (row 5): existing note → task rows read backwards in hubs; the fix is a one-off data migration plus the writer change.
6. **Lossy derived text** (`deriveBody`) feeds FTS, export, MCP and the public page; adopting label-less references (row 3) changes what derived text says about references, so derived text, export and the public renderer change together.
7. **Shared-file serialization:** Notes' store work touches `runtime.web.ts`, `sync/store.ts`, `sync/types.ts` and the migrations folder, which the Tasks data lane also writes; Notes' data block waits its turn in the migration order (runbook rule: one data block at a time).
8. **The store starts for Notes-only members** (§2): today it needs Tasks access; widening its start condition must keep the Tasks tables' reads conditional on Tasks access.

## 5. For the calls (product questions, each with a recommendation)

- **N-1 · The note's right panel.** Views: *Details* (sharing, published, Linked with "Mentioned in", tags), *Comments*, *Outline*; is a fourth, *History* (who changed what, and when), wanted? **Recommend:** three views now (Details · Comments · Outline), History later; anything opened from a note (a task, a contact) stacks as "← item" over them.
- **N-2 · ⌘N and ⌘⇧N.** **Recommend:** ⌘N in Notes makes a new page right here (next to the open page) and opens it in the editor, no window; ⌘⇧N anywhere opens the app's capture already set to Note (the same window as ⌘⇧K → ⌘2), filed at the top level of your notes, with "From: …" when something is open.
- **N-3 · `@` in a note.** Today `@` lists only people and things come through `/`. **Recommend:** the app-wide grammar: `@` lists people first, then things (a person is notified; a thing is linked), `#` links a tag, `/` lists the page's blocks first (headings, lists, checkbox, table, page…), then dates, then things. Mentioning someone who can't open the note warns "Sam can't see this note and won't be notified".
- **N-4 · How a task line looks.** **Recommend:** the same status icon as in Tasks (by category), clicking it completes; Won't do shows its own icon and is never struck through; the line shows its due date ("Fri") and nothing else unless hovered; a task made from a line lands at the top of your Inbox.
- **N-5 · Offline.** **Recommend:** keep writing notes offline (text merges safely); new pages and renames wait and send when back; moving, sharing, trashing and publishing say "Offline". (Tasks is read-only offline except captures; this is a deliberate difference.)
- **N-6 · References on a published page.** **Recommend:** a reference to a page that is itself published links to its public page; any other reference shows only its kind ("a task", "a contact"), never its title, so publishing a page never publishes a private item's name.
- **N-7 · "Edited by …".** **Recommend:** a note's card and hover read "Edited by Sam · Oct 8" (the last person to change the text), as the references research specified.
- **N-8 · Who sees a new page.** Today a new top-level page is shared with the workspace by default, a sub-page follows its parent. **Recommend:** keep that, and offer "Only me" in the capture's destination row; for prepared pages (the hackathon brief, rules, FAQ) the organiser can make a page read-only for the team (the sharing exists; it needs a visible "View only" choice).
- **N-9 · A departed member's published pages.** **Recommend:** when their pages are handed to someone else, they're unpublished and the new owner re-publishes if wanted.
- **N-10 · Several pages at once.** **Recommend:** ⇧/⌘-click in the tree selects; the bottom bar shows "n selected · Esc" with Move · Share · Duplicate · Trash · More, one Undo.
- **N-11 · Templates.** **Recommend:** any page (with its sub-pages) can be saved as a template or duplicated; a template keeps text, structure, sub-pages, references and task lines (as new tasks), and drops comments, history and sharing; templates live in "New page → From template…".
- **N-12 · Reactions on notes.** **Recommend:** the app-wide reaction row (your quick row, any emoji, the workspace's own), on comments only, never notifying (Chat-1, as Tasks and Chat).
