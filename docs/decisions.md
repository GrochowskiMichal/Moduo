- **2026-07-29 · Email history depth is an engine change, not a setting.** "Let the user pick 12 months" looked like a picker; it is not. The desktop engine **only ever walks forward** (the sync cursor records `last_seen_uid` only, with no floor), so raising the window backfills nothing on an existing account; and the full-reset prune **deletes every local row outside the just-fetched UID set**, so any history that did arrive is erased on the next `uid_validity` change. It also fetches the newest 1000 UIDs and *then* discards anything older than 90 days client-side, paying full bandwidth for thrown-away data. Decisions: depth is **per-device local** (on `StoredEmailAccount`, `#[serde(default)]` — the loader swallows deserialize errors into an empty list, so a non-defaulted field would silently erase every connected account); ranges derive from **`UID SEARCH SINCE`**, not a UID count; depth is a **floor** (a promise about what is synced), never a ceiling that evicts; and the **read path is fixed first** (IM-2a) because envelope listing deserializes the whole table ~3× per sync round and is the real wall at 30k+ rows. → [specs/import.md](../specs/import.md)
