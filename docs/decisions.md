- **2026-06-25 · Spine CT-1 link substrate landed (DB + runtime + TS).** The keystone migration ([`supabase/migrations/20260625120000_spine_entity_links.sql`](../supabase/migrations/20260625120000_spine_entity_links.sql)) adds the central `entities` registry, `entity_links` (typed, polymorphic both ends, FK'd into the registry, direction-agnostic partial-unique on a generated `pair_key`, both ends indexed), and `link_suggestion_declines`; ops `links_op_create`/`_set_kind`/`_delete` + helpers `spine_module_permission`/`spine_op__guard`/`entities_op_upsert`/`entities_op_ensure`/`entities_op_tombstone`/`spine_pair_key`, mirroring the Tasks intent-op pattern. Block-specific decisions: **(a)** the spine reuses the **Tasks permission lane** (`permissions_tasks`, owner→admin) as the link-edit gate at alpha — links are task-centric and Tasks is the proving consumer; a dedicated `permissions_spine` is a future one-line migration. **(b)** Registry writes split into two helpers — `entities_op_upsert` (authoritative; an entity's own create/rename op, revives tombstones) vs `entities_op_ensure` (link-time insert-if-absent; never clobbers an authoritative label nor revives a tombstone), so a stale drag label can't corrupt search/@mention. **(c)** `pair_key` is one canonical IMMUTABLE `spine_pair_key()` (forced `COLLATE "C"`) used by the generated column, the ops, and (future) declines, kept byte-for-byte in lockstep with the TS `deriveLinkKey`. **(d)** Links are op-only (RLS = member SELECT; mutations via SECURITY DEFINER ops), tables FK the registry with `ON DELETE CASCADE` while normal deletes tombstone (`deleted_at`). Server invariants (AC1–AC5) were **validated on real Postgres 17** (the moduohyb prod DB) via a **rolled-back transaction** — 15/15 checks green (create/idempotent/direction-agnostic/self-link/bad-kind/permission/activity/registry/tombstone/no-revive/soft-delete + `pair_key`==`spine_pair_key`), incl. correct normalization of the **legacy `read`/`write`** permission vocabulary that's actually in the prod schema; prod left byte-clean. Migration is **deploy-ready** (Supabase branching needs the Pro plan, so it wasn't applied to prod from here — that's the deploy step); regenerate `src/types/supabase.ts` after the prod apply. → [specs/connective-tissue.md](../specs/connective-tissue.md)
