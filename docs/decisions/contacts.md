- **2026-07-02 · Fix pack FX-9 landed (drag-to-link on /contacts) — Wave 1.5 complete.** AC12, the **first live consumer of the CT-3 drag machinery**, no migration. Decisions: **(a)** the drag source is gated behind a `draggable` prop and rendered via a `DraggableRow` wrapper (only mounted when `draggable`=true) so `useDraggable` is never called outside a `DndContext` — the directory stays usable (stories/other contexts) without one. Pointer `listeners` only (not `attributes`) so the row keeps its click-to-select semantics (no extra tab-stop/role); `PointerSensor` distance:6 separates click from drag. **(b)** Collision detection is **`pointerWithin` only** (same call as CAL-3) — an out-of-hub release is a no-op, never a stray link. **(c)** **Duplicate rejection is an explicit client guard**, not the server: `links_op_create` is idempotent (`ON CONFLICT DO NOTHING`, returns the existing row), so a re-drop would otherwise pop a misleading Undo toast on a pre-existing edge — the page checks the **drop-target's** direct-link keys (`contactDirectLinkKeys` from the hub roll-up; `companyHub.directLinkKeys` newly exposed from the company's own links, NOT the union which mixes inherited rows) and toasts "Already linked". Self-drop is blocked twice (targetAccepts + guard). **(d)** **A person↔company works-at drop dual-writes the denormalized `company_id` FK** — `onDragEnd` layers `updateContact({setCompany})` on top of the spine-generic `createLinkWithToast` (which only writes the edge), so the contact header company chip reflects a drag, matching `setCompany` + the entry modal. General lesson recorded in gotchas: any CT-3 consumer with a denormalized mirror of a link must add its own FK write. **(e)** Drag is edit-gated everywhere; the drag e2e stays a manual-test surface (unsimulable in worktrees). verify green (447 tests). **Migration `20260702160000_companies_delete.sql` applied to prod 2026-07-02** (MCP reconnected; authed rolled-back round-trip green, prod byte-clean; `src/types/supabase.ts` updated) and the stale `moduo-mcp` connector redeployed (contacts/links/tasks agent tools live, verify_jwt=false). → [specs/contacts-v3-fixpack.md](../../specs/contacts-v3-fixpack.md)

- **2026-06-27 · Contacts CO-2 Directory + ContactHub landed ("the great moment").** The contact page is a pure READ over the spine — the reusable pieces are the pure reducer [`contacts/rollup.ts`](../../src/features/contacts/rollup.ts) (`buildContactRollup` composes the spine's `rollupSections` + derives `lastTouchAt`/`openTaskCount`; `lastTouchLine` renders the quiet one-liner; unit-tested, AC2) and the presentational [`ContactHub`](../../src/features/contacts/ui/contact-hub.tsx) (header + `LastTouchLine` + spine `EntityHub` variant=page + `ActivitySection`) fed by [`useContactHub`](../../src/features/contacts/hooks/use-contact-hub.ts). Decisions: **(a)** **there is no "log activity" affordance** — the record is current by construction (links + activity), the defining CRM-anti-pattern we refuse. **(b)** **last-touch is an on-the-fly approximation** = max(the contact's own `module_activity`, each link's `createdAt`); it does **not** read activity on the *linked* entities (a linked task edited later doesn't bump it). Per decision 4 this stays on-the-fly; promote to a materialized last-touch view only if profiling misses 200ms. **(c)** **open-items needs live task status** (the registry carries none), so `useContactHub` lazily loads the tasks bundle (only when the contact has task links) to build the open-task set the pure reducer intersects with; payments degrade to 0 until Finance ships. **(d)** **`runtime.tasks.listActivity` was tasks-pinned** (`module='tasks'`) — fixed to an **optional module filter**: the Tasks caller now pins `module:'tasks'` (unchanged behavior), a spine entity (contact/company) reads **entity-scoped across all modules** (its touches log under `module='contacts'`, never 'tasks'). This was a blocking validator find — a contact's trail was silently empty. **(e)** **Contacts rides the Tasks permission lane** in the UI too (`canEdit = modulePermissions.tasks === 'edit'`) — `modulePermissions` exposes only notes/tasks; a dedicated `contacts` key lands with `permissions_contacts`. **(f)** The **company hub is minimal** in CO-2 (name + roll-up + activity); the People-union group + the right context strip (suggestions/tags/quick-actions) are **CO-4**.
