- **2026-06-27 · Contacts CO-5 MCP manifest + "Needs attention" widget landed — Wave 1 (Contacts) complete.** The module DoD. Decisions: **(a)** **the connector mirrors all 6 contacts writes + 3 reads** ([`moduo-mcp/modules/contacts.ts`](../../supabase/functions/moduo-mcp/modules/contacts.ts)) — including `contacts_import` (agent bulk-add) — unlike the spine connector which omitted notif/decline; contacts has no agent-hostile ops. `contacts_get` returns the contact + its links (the roll-up read). **(b)** **`contacts_search` uses two `.ilike` queries (name, email) merged**, NOT a `.or()` — the PostgREST `.or` grammar is delimited by `,()` `.` so a query like "acme.com" would malform it (the safeToken lesson from links.ts, generalized). **(c)** **"Needs attention" is a pure selector over cheap inputs** ([`needs-attention.ts`](../../src/features/contacts/needs-attention.ts)): last-touch = the contact's `updatedAt` proxy (CO-2 deferral; the precise cross-entity last-touch is post-alpha), overdue-follow-up = a real links→tasks join (3 reads, no fan-out). Thresholds (14d/30d) are constants (decision 7). **(d)** **idleness keys off the default status ids** (`active`/`lead`) — a *renamed* status won't trip no-touch/stale-lead; acceptable at alpha (thresholds "later configurable"), noted as a limit. **(e)** the widget is **quiet by construction** (muted icon + detail, never destructive/red — AC11's "no guilt wall"). **Validator-caught blocker:** `tasks.due_date` is a **timestamptz** (stored from local-midnight→UTC), not a `YYYY-MM-DD` string — overdue detection must normalize it to a local calendar date first (a raw lexical compare is off-by-one east of UTC). See [[gotchas]]. Connector is a Deno edge fn (not typechecked by `bun run verify`) — deploy-gated; verify green (249 tests). → [specs/contacts.md](../../specs/contacts.md)

- **2026-06-27 · Spine CT-7 Tasks adoption + MCP manifest + dashboard widget landed (Wave 0 spine complete).** **AC13 (the dual-path)** is a **mirror trigger, not a cutover**: migration [`20260627130000_tasks_relations_to_links.sql`](../../supabase/migrations/20260627130000_tasks_relations_to_links.sql) adds a SECURITY DEFINER AFTER INSERT/DELETE trigger on `task_relations` that registers both task entities (`entities_op_ensure`) and mirrors the dependency into `entity_links` (`relation_kind='blocks'`, idempotent via the live partial-unique index) + a backfill for existing rows. Decisions: **(a)** the **shipped blocked-by read path is untouched** — the app still computes "blocked" from the `task_relations` bundle ([`helpers.ts`](../../src/features/tasks/helpers.ts)); the trigger only *adds* the spine edges. This is the zero-regression guarantee and sidesteps the new-RPC-on-a-hot-path deploy-gap (no runtime write-path change). **(b)** The mirror **logs no `module_activity` row** — the `task_relations` write is the canonical action and logs nothing today; adding activity here would change the shipped blocked-by trail (a behavior regression). The blocks edge is a derived shadow during transition; attributed activity arrives when the relation write becomes a real intent op. **(c)** "blocked-by works via entity_links" is proven by the pure converter [`tasks/blocks-bridge.ts`](../../src/features/tasks/blocks-bridge.ts) (`blocksLinksToRelations`) + a unit test that runs the *real* shipped `blockedTaskIds`/`frontierTasks` over link-sourced edges (same data, different source table). **AC12**: app-side [`linksModuleManifest`](../../src/features/spine/ops-manifest.ts) in [`module-registry.ts`](../../src/lib/module-registry.ts) (+ test) and connector-side [`moduo-mcp/modules/links.ts`](../../supabase/functions/moduo-mcp/modules/links.ts); the **"Recently linked" dashboard widget** (runtime `spine.recentLinks` = one indexed `entity_links` read + one batched registry lookup; pure [`spine/recent.ts`](../../src/features/spine/recent.ts) shaper). **Two recorded deferrals:** **(1)** the `moduo:entity:open` deep-link event (dispatched by this widget and CT-4's EntityRefChip) has **no host listener** — clicking dispatches the right `{type,id}` but nothing routes it to a hub yet; wiring the app-shell listener + per-page entity-focus is a shared cross-cutting follow-up (the CT-4 dark-ship). **(2)** Tasks register into `entities` **only when they participate in a dependency** (via the trigger) — a dependency-free task isn't yet searchable/@mention-able; **full per-task registry adoption** (upsert on every `tasks_op_*` create/rename + an all-tasks backfill) is a follow-up beyond CT-7's `task_relations`-dual-path scope. Migration deploy-ready but unapplied (Supabase MCP on the wrong org). → [specs/connective-tissue.md](../../specs/connective-tissue.md)
