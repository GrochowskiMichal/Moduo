- **2026-10-17 · PLAT-4: the web app on Cloudflare: the Worker serves the SPA shell itself (`not_found_handling: "none"`), config is injected per environment, previews are versions of the staging Worker, no preview redirect allowlist.** `apps/app/wrangler.jsonc` defines `staging` (`moduo-app-staging`, preview URLs on) and `production` (not deployed until PLAT-8). Files that exist never reach the Worker. - **2026-10-17 · PLAT-3: CI skips work through the Turborepo cache, not `--affected`; PR runs read the cache with the signing key but can't write.** The remote cache is our own Worker + R2 (`infra/turbo-cache`, about 150 lines of the v8 artifacts API, deployed by `turbo-cache.yml`) with two tokens: the Worker refuses `PUT` with the read token (403). Push runs on `develop`, `main`, `mike`, `maciej` (the spec said develop and tags only; the personal branches were added so the sync PR into develop finds a warm cache) get the write token through the `turbo-cache-write` environment (branch policy: those four + `v*` tags); PR runs get the read token and `TURBO_CACHE=local:rw,remote:r`. Artifacts are HMAC-signed (`remoteCache.signature`, `futureFlags.longerSignatureKey`). `checks.yml` runs every task and lets the hash decide; a docs-only PR (Markdown anywhere, non-code files under `docs/`/`specs/`) skips lint and tests entirely (push runs never skip: their `before` may not have passed) and `static-checks` still passes. Personal-branch pushes now run the full suite, so the cache is warm for the sync PR into develop.
  - *Why not `--affected`:* it follows only package.json dependencies, and the app reads `supabase/functions/_shared` (contracts) and `scripts/` through aliases and `$TURBO_ROOT$` inputs. Measured: a change to `contracts/vocabularies.ts` made `--affected` run only `@moduo/backend`, skipping the app's typecheck and tests. The hash sees those inputs, so cache hits give the same speed-up without the hole.
  - *Why PRs get the signing key:* turbo can't verify a signed artifact without it. Measured with turbo 2.11.7: no key (and `TURBO_SIGNATURE=false`) turns every remote read into a miss, a wrong key too. So "no key on PRs" would mean PRs never read the cache. Writes stay closed by the token, which the Worker enforces. To poison the cache you need the key plus either the write token or the Cloudflare token, and neither reaches a PR run of `checks.yml`. Gaps that are still open: push runs give the write token to the whole job, including `bun install` and the tests. `CLOUDFLARE_API_TOKEN` is still a repo-level secret, so a same-repo PR that edits a workflow could read it. Moving it into an environment is left to PLAT-4, which decides how previews deploy.
  - *Rejected:* `TURBO_REMOTE_CACHE_READ_ONLY` (deprecated in turbo 2.11; `TURBO_CACHE=…remote:r` is the same thing); the OSS `turborepo-remote-cache-cloudflare` (more surface than we need, and pinning a Worker means vendoring it); Vercel Remote Cache (we're leaving Vercel).

- **2026-10-14 · End-to-end runs on the local stack go through `scripts/agent/e2e.sh`: one run at a time across all worktrees, and each worktree starts its own dev server on its own port (agent's choice, deferred to by Maciej: confirmed for building, revisitable).** On the Tasks v3 build 170 of 513 builder e2e runs (33%) failed, 168 of those passed on a later run, and 44% of all e2e minutes went to failing runs.
