# Decisions: Desktop app, Tauri, releases

Full entries for this area, newest first. The one-line index of every area is [docs/decisions.md](../decisions.md). Add new entries at the top here **and** a one-line pointer in the index.

- **2026-10-07 · Both desktop release channels run one shared workflow, and only the `.dmg` is notarized.** `desktop-release.yml` (staging) and `desktop-release-prod.yml` (production) call `_desktop-release.yml` with their channel settings, so a fix can't reach one channel and miss the other. The Mac build makes one Apple submission (the `.dmg`, which covers the `.app` inside it), and its wait is time-limited and can be resumed. The release publishes once the Mac build is notarized. Windows doesn't block it: when the Windows build fails, `latest.json` leaves Windows out rather than pointing an old installer at a newer version. CI scripts are checked out from the workflow's own commit, so a production build of an older `prod-app` still gets the current signing logic. Staging cancels a superseded run; production queues a second run behind the first.

- **2026-10-07 · Rust crates and Rsbuild move to the newest stable, not their pre-releases.** Tauri stays on 2.12.1 (the 2.12 IPC-channel fix); 3.0.0-alpha.4 is a breaking rewrite. Rsbuild is 2.2.12 — its beta/alpha/rc/canary tags are all older than that stable. redb stays 2.6.4 because 4.x cannot open the 2.x files already on disk (mail, notes, identity). imap stays 2.4.1; 3.0 is alpha. Everything else direct went to its newest stable major (`reqwest` 0.13 on rustls, `argon2` 0.6, `aes-gcm` 0.11, `rand` 0.10, `keyring` 4, `bip39` 3). Stored secrets stay compatible: Argon2 PHC strings still verify, AES-GCM blobs stay 12-byte nonce plus ciphertext, BIP39 seeds still derive the same way. Two speed settings turned on with the bumps: Rsbuild persistent `buildCache` (keyed by web vs desktop) and prefetch of async route chunks. Subresource integrity and a content-security policy were left off — the desktop shell loads its own files and a policy written blind would break the app. → `src-tauri/Cargo.toml` · `rsbuild.config.ts`

- **2026-10-07 · Desktop Rust is pinned to nightly-2026-10-06, with the parallel front end on.** The shell builds with that nightly (`src-tauri/rust-toolchain.toml`), and `--jobs-frontend=0` gives the compiler one front-end thread per core. GitHub Actions installs the same nightly. `Cargo.toml`'s `rust-version = "1.90"` is the minimum Tauri 2.12 requires; the pin is the compiler we actually run. → `src-tauri/rust-toolchain.toml` · `src-tauri/.cargo/config.toml`

- **2026-07-13 · DF-19f-quit FIXED — it was shipping non-functional (both the ⌘Q *and* window-close confirmations never fired).** A with-designer smoke test proved the two entries below (the `RunEvent::ExitRequested` handler + the JS `window.confirm` guard) were **both dead code**, from two independent Tauri v2 facts: **(1)** macOS ⌘Q does **NOT** raise the preventable `RunEvent::ExitRequested` — the predefined Quit menu item calls `NSApplication terminate:` directly → straight to `RunEvent::Exit` (instrumented `eprintln!` confirmed, even with `confirm` hardcoded true); **(2)** in the v2 webview `window.confirm()` is **async** (returns a Promise) and gated by a `dialog:allow-confirm` capability we don't grant, so `!window.confirm(…)` is always falsy and `preventDefault` never ran. **DECISION: unify BOTH gestures on ONE native Rust dialog** ([lib.rs](../../src-tauri/src/lib.rs)): **(a)** replace the predefined Quit with a **custom `MenuItem`** (id `moduo-quit`, ⌘Q accelerator) inside a menu that mirrors `tauri::menu::Menu::default` v2.11 item-for-item (Copy/Paste/Undo/Fullscreen/Window/Help preserved) — ⌘Q now fires `on_menu_event`; **(b)** window close → a `WindowEvent::CloseRequested` handler (`.on_window_event`) scoped to the `"main"` window, `api.prevent_close()` + the same dialog; **(c)** on confirm both `app.exit(0)` (full exit — chosen over destroying just the window, so no windowless dock zombie), which runs the normal `RunEvent::Exit` cleanup and does NOT re-raise `CloseRequested` (verified in 2.11 source → no exit deadlock); `app.exit(0)` is safe from these deferred callbacks (not inside a `RunEvent` frame), so the old `std::process::exit` hack is gone. **(d)** JS is now **mirror-only** — the broken `onCloseRequested`/`window.confirm` guard is deleted, `useConfirmBeforeQuit` only pushes the pref to Rust; **(e)** `core:window:allow-destroy` **removed** (no JS destroy path left); `dialog:default` covers the native dialog. Reviewed by 2 agents against the installed Tauri/muda/dialog sources → **no correctness bugs** (applied their `"main"`-window guard + doc-comment fixes). `bun run verify` **1213 green** + `cargo check` clean + debug binary links. **Supersedes the two entries below.** ⚠ Still needs a real-desktop pass (the crux: ⌘Q now SHOWS the dialog); a sub-second boot race (pref default false until the webview mirrors it) is a pre-existing, documented limitation. → [docs/gotchas.md](../gotchas.md) §Tauri · [docs/testing/df-19f-quit-cmdq.md](../testing/df-19f-quit-cmdq.md)

- **2026-07-11 · Proposal C executed — dead Rust graph/embeddings sidecar pruned; `sync` feature-gated behind `lite`.** Removed the fully-dead graph + embeddings subsystem (`graph_helix/`, `embeddings/`, `commands/graph.rs`, `commands/embeddings.rs`, the `AppState` `graph`/`embeddings`/`indexer` fields + their `generate_handler!` registrations, the runtime `graph` namespace across `runtime.types.ts`/`.tauri.ts`/`.web.ts`, the dead redb graph tables/methods + domain `GraphNode/Edge/Hybrid*` types) and dropped the now-orphaned Cargo deps **`helix-rs` + `ort` + `tokenizers`** (Cargo.lock −689 lines — the ONNX/tokenizer transitive tree is gone). **Key divergence from the memo/Graphify premise (which called these "isolated, in no coupling hotspot, touches zero feature code"): they were NOT code-isolated.** `graph_helix` was woven into the **live email engine** via `commands/email/graph_outbox.rs` — `queue_graph_upsert_for_envelope`/`schedule_graph_outbox_flush` were called from ~11 sites across `email.rs`/`email/sync.rs`/`email/realtime.rs`, and `queue_*` wrote an `email_graph_outbox` redb row on **every** envelope sync (only the *flush* was gated off behind `state.graph.is_enabled()`, false unless `HELIX_SIDECAR_PATH` is set). So the subsystem was **runtime-dead** (no consumer of its outputs: graph queries unwired, redb graph tables never read, outbox written-but-never-flushed) but **compile-coupled** into email — removing `helix-rs` required excising that dead tendril + its 2 email parsing helpers + the `StoredGraphOutboxEntry` model. Email functionality is byte-identical; only dead redb writes stopped. **`sync/` (redb↔Supabase cloud worker) was NOT deleted but feature-gated behind a new `lite` Cargo feature** (off by default): it's live-wired from `auth.rs` (starts on cloud-session accept) yet its push side is never fed (`sync::enqueue` has zero callers) and its own docstring says `notesV2` (JS) superseded the note-CRDT path — so it's kept as the offline/"lite"-build seed, consistent with keeping redb + the local-auth/workspace/mnemonic vault (all **left intact**, per instruction). **Kept load-bearing:** email engine, calendar/CalDAV sync, time-tracking, integrations. **Verified:** `cargo check` **default + `--features lite`** both clean (0 warnings), `cargo test` 54 Rust tests pass, `bun run verify` green (1022 tests). Decision to touch the load-bearing email engine + feature-gate (vs delete) sync was the designer's explicit call. → [docs/onboarding/backend-refactor-memo.md](../onboarding/backend-refactor-memo.md) §3 · [docs/gotchas.md](../gotchas.md) §Rust · [docs/testing/prune-dead-rust-sidecar.md](../testing/prune-dead-rust-sidecar.md)
