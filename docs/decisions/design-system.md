- **2026-10-08 · DS-2 landed: primitives use the state layer, selection is tint-only, hover ≠ current everywhere it collided.**
  - **The ladder:** rest → `bg-state-hover` (5%) → `bg-state-active` (9%; current page, pressed, highlighted option) → **`bg-state-active-hover`** (14%, new). The new step is for hovering something that already has a fill. A translucent fill *replaces* an opaque one, so a filled control can't hover to the hover step (it would get darker). The secondary button rests on active and hovers to active-hover. Outline and ghost hover to the hover step and press to active.
  - **Selection looks behind one token:** list rows use `SELECTED_ROW` (`bg-state-selected ring-1 ring-inset ring-state-selected-edge`). Cards and bordered options (board cards, booking chips, option cards) use `SELECTED_OPTION`, which always carries `ring-state-selected`, as in the comp. Both live in `src/components/ui/selection.ts`, so the 13 call sites share one recipe. **`--state-selected-edge` ships as the 32% ring (tint + hairline).** The reason is that on the default mono accent the tint alone is about one just-noticeable step from "active". Setting it to `transparent` gives tint-only. It's the designer's call (spec: "decided visually in DS-2").
  - **Current vs selected:** the current destination in a rail or nav (module tab, workspace, email scope, settings section, the open chat channel, the access rail) is neutral `bg-state-active`. The accent is kept for selected items in lists. The five accent bars and the task-card accent border are gone. Chat's mention tint and attention bar, the unread divider, inline mentions and search marks are status: they compose `--primary` directly.
  - **Menus, select and command:** the highlighted option takes the active step, because Enter acts on it. A submenu trigger stays on active while open.
  - **Raised plates** (SegmentedControl, the default Tabs list, the email-connect provider tabs) use `bg-control-raised shadow-control-raised`. **Found while building:** the icon-only view switcher never showed its current segment, because the tooltip wrapper overwrote each segment's `data-state`. The plate is now keyed on `aria-checked` (gotchas/ui.md).
  - **`--selected-bg` / `--selected-border` have no consumers left,** but stay defined until DS-5 so a branch cut before DS-2 still renders until it merges. `src/components/selection-guard.test.ts` fails on any use, and on any vertical accent bar outside two status allowlist entries (calendar focus edge, chat attention bar).
  - **Also fixed on the way:** `cn()` now knows the named @theme shadows (`control-raised`, `overlay`). tailwind-merge had filed them under shadow colour, so an override like `shadow-none` didn't replace them. Ghost and outline buttons style `aria-pressed` (active step, hover one up), so chat's header toggles and the notes format toolbar no longer force `bg-accent`; with the new translucent hover, that would have made them darker on hover.
  - **Not in DS-2** (left for DS-5): the remaining ~100 hand-written `hover:bg-accent`, the user-menu/focus-chip triggers, the appearance pickers' neutral option cards, and bare `transition-colors` without motion tokens outside the touched lines. Visual baselines for `tests/visual/state-ladder.spec.ts` are captured by a human.

- **2026-10-08 · DS-1 landed: the state layer re-resolves in every appearance scope, thin token scrollbars are the global default, and Storybook switches every appearance axis.**
  - **How the tokens scope (differs from the spec's wording).** The spec had the utilities inline each `color-mix()` through `@theme inline`. Built instead: each formula is declared once, on `:where(:root, [data-theme], [data-shade], [data-accent])` (tokens.css §5b; zero specificity, so the light `--control-raised` override wins wherever it sits), and `@theme inline` maps the utilities to `var(--state-…)`. A var()-based custom property resolves where it is declared, so every wrapper carrying an appearance attribute recomputes it from its own `--primary` / `--foreground` / `--muted`. Why: one formula per token; plain `var()` consumers (CSS, `[var(--…)]`) scope the same way as utilities; and `--control-raised` needs a different formula on light, which a single inlined utility can't express. Trade-off: a wrapper that changes `--primary` without one of those attributes doesn't re-resolve them (gotchas/ui.md). Verified live: on `/auth` with a blue accent stored, `--state-selected` inside `preWorkspace()`'s wrapper is mono and blue outside it.
  - **Tokens.** `--state-hover` 5% / `--state-active` 9% foreground, `--state-selected` 13% / `--state-selected-ring` 32% primary, `--hairline` 10% foreground, `--control-raised` (14% foreground over `--muted` on dark, the card on light), `--scroll-thumb` 16% / `--scroll-thumb-hover` 32% foreground. One addition the spec implied ("card + shadow on light"): `--shadow-control-raised` (`shadow-control-raised`), a zero shadow on dark and `--shadow-sm` on light. `ring-state-selected` is the 32% ring through Tailwind's `--ring-color-*` namespace, while `bg-state-selected` is the 13% tint.
  - **`--selected-bg` / `--selected-border` moved into the same scope block**, values unchanged. Pre-workspace pages (the public booking page's chips) now show a mono selection instead of the visitor's hue, matching 2026-07-27's "pre-workspace surfaces are always monochrome".
  - **Measured:** across all 96 theme × shade × accent combinations and four surfaces (card, background, popover, muted), every adjacent pair of rest / hover / active / selected differs by ΔE(OKLab) ≥ 0.024; the legacy hover (`bg-accent`) and active (`bg-secondary`) are identical on dark. The closest pair on dark is active vs selected (≈ 0.027 at worst: teal on the cool shade, mono on popovers), which the selection hairline separates: input for DS-2's tint vs tint + hairline call.
  - **Scrollbars.** A base-layer `*` rule (standard properties) plus `::-webkit-scrollbar` rules (pre-18.2 WKWebView), token-coloured. `.scrollbar-thin` stays as a no-op alias, `.no-scrollbar` is the opt-out on both paths, and `.pane-scroll` (`scrollbar-gutter: stable`) sits on 27 pane scrollers in Tasks, Notes, Calendar, Email, Contacts, Chat and Settings (centers, rails and inspectors). Not on the shell wrappers (their children scroll), the calendar hours grid (its header sits outside the scroller), the calendar rail (its fixed-width mini month would overflow), the notes Outline (it never scrolls today), Board columns, the Timeline canvas, dashboard widgets or Radix `ScrollArea`, whose thumb now uses the same token. The booking day-chip row moved from `[scrollbar-width:none]` to `.no-scrollbar`, and a test now fails on the bare utility.
  - **Storybook** builds its theme / shade / accent / density / radius / font menus from `APPEARANCE_OPTIONS` and reads the globals through `parseAppearance` (both now exported from `appearance.ts`). The decorator is keyed per story and sets one attribute per axis in a layout effect: every story starts from the toolbar's values, and a story that pins an axis itself (the widgets gallery's density) keeps it until that one global changes. It leaves `data-tabs` alone. The retired text-size menu is gone. `Foundations/StateLadder` shows the layer.

- **2026-07-27 · The app accent is MONOCHROME by default; hues are opt-in; pre-workspace surfaces are always monochrome** (designer-ratified 2026-07-27). Moduo's primary look is **black + gray + white, no hues** — a colored accent is a *user choice* in Settings → Appearance → Accent, never the shipped identity. **Found in audit:** the accent was hardcoded pink in 4 places — `tokens.css` `:root` bound `--primary/-hover/-active/--ring` to `var(--pink-*)`, `appearance.ts` `DEFAULT_APPEARANCE.accent = "pink"`, the dormant Subframe mirror `src/ui/theme.css`, and the picker listed Mono last.
