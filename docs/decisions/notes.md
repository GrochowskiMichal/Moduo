- **2026-07-30 · IM-1: an imported note's id is derived from Notion's page id, not from its path — and uniqueness is guaranteed, not assumed.** Two coupled decisions. **(a) Idempotency needs stable ids.** `notes_op_import` has always been idempotent *per row id*, but the wizard minted `crypto.randomUUID()` per node, so a re-run inserted a second copy of all 350 pages — the op's idempotency was unreachable. Ids are now derived (a synchronous 128-bit FNV-1a digest, v4-shaped; `crypto.subtle` is async and this path is sync). **The seed is Notion's own 32-hex page id** when the export carries one, falling back to the normalized path. Seeding on the path is unsafe in *both* directions: same-titled sibling pages normalize to the same path (Notion appends the hex precisely because titles repeat), and a page that merely *moved* between exports would re-key and duplicate. The spec already called the hex "the join key". **(b) A duplicate id is not an error — it is silent data loss**, because the op resolves id-exists by skipping the row, so a collision deletes a page and reparents its children under its twin. `assignImportIds` therefore *guarantees* distinctness with a deterministic discriminator rather than trusting the seed. **Rejected:** stripping the export wrapper by longest-common-prefix — it worked, but it made every path (and so every id) a function of the shallowest file in the drop, so one new top-level teamspace re-keyed all 350 notes and a re-import duplicated the workspace. The wrapper is now **pattern-matched per entry** (`Export-<uuid>/`, then the workspace bucket), which is stable across drops. Also: the app's first `Progress` primitive lands here (hand-rolled, no new dependency) on a **movement** motion token, since it animates width. → [import.ts](../../src/features/notes/import.ts) · [import-zip.ts](../../src/features/notes/import-zip.ts) · [progress.tsx](../../src/components/ui/progress.tsx)
