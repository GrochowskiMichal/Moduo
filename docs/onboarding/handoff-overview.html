Architecture at a glance

Two runtimes, one seam. All data flows through getRuntime(); runtime.web.ts is the only file that talks to Supabase.

Source of truth
Supabase (cloud)
  • Auth, workspaces, tasks, spine, contacts, notes, calendar, prefs, dashboard
  • Writes = SECURITY DEFINER intent-op RPCs (permission + invariant + activity in one txn)
  • Reads = RLS-filtered selects
Paused — lite-version only
redb (desktop)
  • Genuinely native: the email IMAP/SMTP engine, OAuth calendar sync, time-tracking
  • Dead/dormant: graph + embeddings, the local-auth vault, the sync worker
  • Never load-bearing for a new feature

The module contract

A module isn't “done” until it ships all four pillars — that's how new modules get AI access, activity and notifications nearly for free.

Guardrails that constrain change

Async multiplayer (not live collab), AI is MCP-only, email is desktop-first hybrid, and no abstract graph-view UI — the moat is felt through one-gesture links, never shown.

The one open backend question

“Refactor the backend” is four different proposals with an order-of-magnitude cost spread. Pin down which before anything else. Full reasoning in backend-refactor-memo.md.

AReplace Supabasevery high

Re-express 43 migrations, re-verify every invariant on live data, rebuild the MCP layer. Hard to justify pre-alpha.

BMove logic out of plpgsqlthe debate

Doable incrementally behind the seam — but it touches the “agents write safely for free” pillar. Do it per-op, not as a sweep.

CPrune the dead Rustdo this

The genuine win. Delete graph/embeddings + gate the paused vault. ~1–2 days, zero feature-code impact.

DReshape the data modelcase by case

Some are one-migration tweaks; ripping the entities registry would hit the moat.

Recommendation: the cloud backend is coherent and done — the real deletable debt is dead Rust, not Supabase. Do C now, keep Supabase + intent-ops through alpha, evolve B incrementally only where an op hurts, and refactor the whole backend only against a concrete trigger (scaling wall, security hole, a feature the model can't express, or blocked velocity).
