# Gotchas: Tauri desktop shell and desktop stores

Read before working in `src-tauri/`. Index of all areas: [docs/gotchas.md](../gotchas.md). Each entry: the trap, why it happens, what to do instead. A trap that bites twice should become a hook, a lint rule or a test.

## Tauri / desktop shell

- **macOS ⌘Q does NOT raise the preventable `RunEvent::ExitRequested` — Tauri v2's predefined Quit menu item calls `NSApplication terminate:` directly, going straight to `RunEvent::Exit`.** This silently broke DF-19f-quit's first attempt: the whole `ExitRequested { api } => api.prevent_exit()` handler was **dead code** for ⌘Q (instrumented `eprintln!` confirmed ⌘Q → `Exit`, never `ExitRequested`, even with `confirm` hardcoded true). **Fix (2026-07-13):** replace the predefined Quit with a **custom `MenuItem`** (id `moduo-quit`, ⌘Q accelerator) inside a menu that otherwise mirrors `tauri::menu::Menu::default` (so Copy/Paste/Undo/Fullscreen/etc. keep working), and confirm in `.on_menu_event`. `terminate:`-based quits you STILL can't intercept: dock right-click → Quit, and system logout/shutdown — accepted limitation (`RunEvent::Exit` still runs worker cleanup). → [src-tauri/src/lib.rs](../../src-tauri/src/lib.rs)
- **In the Tauri v2 webview, `window.confirm()` is ASYNC (returns a Promise) and gated by a `dialog:allow-confirm` capability we don't grant — so `if (!window.confirm(…)) e.preventDefault()` NEVER prevents.** `!Promise` is always falsy, so the branch dead-ends (devtools: `window.confirm(…)` → `Promise {pending}`, then "dialog.confirm not allowed. Command not found"). This was DF-19f-quit's SECOND independent bug — the JS window-close guard did nothing, and a code comment even claimed `window.confirm` was "synchronous in the webview". **Never use `window.confirm`/`alert`/`prompt` for control flow in the webview.** Fix: moved the window-close confirm to Rust too — `WindowEvent::CloseRequested` (`.on_window_event`) → `api.prevent_close()` + a native `tauri-plugin-dialog` confirm, unifying ⌘Q and window-close on ONE native dialog. → [src-tauri/src/lib.rs](../../src-tauri/src/lib.rs)
- **You CANNOT call `app.exit()`/`app.restart()` from INSIDE the `.run()` `RunEvent` handler in Tauri v2 (it re-enters `ExitRequested` → loop/panic) — but you CAN from a deferred event callback** (`.on_menu_event` / `.on_window_event` / a dialog `.show()` closure), which runs on a later loop turn outside the `RunEvent` frame. The unified quit path calls `app.exit(0)` from those callbacks (which runs the normal `RunEvent::Exit` cleanup — `stop_all_idle_workers()` — so no separate `std::process::exit`). Verified in the 2.11 source: `app.exit(0)` goes through `request_exit` and does **not** re-raise `WindowEvent::CloseRequested`, so the window-close handler won't re-prevent the exit. (tauri issue #5500.) → [src-tauri/src/lib.rs](../../src-tauri/src/lib.rs)
- **Don't `blocking_show()` a `tauri-plugin-dialog` message dialog on the event-loop (main) thread — it can deadlock.** Use the non-blocking `.show(|confirmed| …)`; the callback fires on a later loop turn. Guard repeated gestures with an `AtomicBool` (`quit_prompt_open`): `.show()` returns immediately and leaves the loop live, so a second ⌘Q/close would stack another dialog — only the first opens one, the rest no-op; Cancel clears the guard. `dialog:default` covers the native dialog, and **`core:window:allow-destroy` is no longer needed** — the JS `onCloseRequested`/`destroy()` path was removed, so all quit confirmation is native now. → [src-tauri/src/lib.rs](../../src-tauri/src/lib.rs)
- **`@tauri-apps/api/window` is NOT web-stubbed (only `/core` is aliased in [rsbuild.config.ts](../../rsbuild.config.ts)).** A static import breaks/fattens the web bundle; use a `isTauriRuntime()`-guarded **dynamic** `import("@tauri-apps/api/window")` so web never evaluates it (Rspack code-splits it into a chunk web never fetches). If a future feature needs it statically in shared code, add a web alias stub like the `/core` one. → [src/lib/tauri-api-stub.ts](../../src/lib/tauri-api-stub.ts)
- **To LIVE-VERIFY a native macOS desktop gesture (⌘Q, red-button close, native dialogs) when the `computer-use` grant is declined, script the desktop directly from Bash.** Recipe proven on DF-19f-quit (2026-07-13): build a **recognizable** app first — the bare debug binary has no bundle id, so build a debug `.app` (`MODUO_TARGET=desktop rsbuild build` → `… tauri build --debug --bundles app`; debug deps are cached so it's ~40s, far faster than release) and launch **your** build by explicit path (`open src-tauri/target/debug/bundle/macos/Moduo.app`) because a stale `/Applications/Moduo.app` shares the `com.moduo.desktop` bundle id and LaunchServices may otherwise pick it. Then: `screencapture -x out.png` to observe (Screen-Recording perm is already granted to this env), `osascript … keystroke "q" using command down` for ⌘Q / any shortcut, `osascript … click button 1 of window 1` for AX-exposed native controls (the red close button is `AXCloseButton`), and — since **WKWebView content is NOT exposed to AppleScript AX** (`entire contents` of the web area is empty; can't click webview buttons/toggles/fields that way) — a tiny **Swift CGEvent** clicker/scroller for coordinate clicks into the webview (`cliclick` and python-`Quartz` aren't installed; `swiftc` is). Coordinate conversion: logical points = Retina physical px ÷ 2. Verify clipboard round-trips with `pbcopy`/`pbpaste`. To force a toggle-gated Rust path ON without a signed-in pref, temporarily hardcode the `AppState` default and **revert after** (never commit it); re-prove the real path on a rebuild with the true default.

## Desktop email store (IM-2a)

- **A redb key that embeds a mutable field is a row leak, not just an ugly key — and the "obvious" fix (make the key stable) can destroy the index.** `envelope_order_key` is `{account}::{folder}::{reverse_ts}::{uid}`; a message with no `Date:` header gets `now_iso()` on every fetch ([`sync.rs`](../../src-tauri/src/commands/email/sync.rs) `fetch_envelopes_for_uids`), so every refetch wrote a **second** order row and orphaned the first — unbounded growth, invisible because nothing reads that table yet. Making the key stable is the wrong instinct: strip the timestamp and the "order index" is just a duplicate of the envelope key. The fix is to recover the **previous** row's key (re-mint it from the stored row's fields) and delete it in the same transaction as the new write. Two consequences to remember: the derivation is **re-minted, not stored**, so changing the key format strands every existing row; and a point delete no longer sweeps pre-existing orphans the way the old full-table scan incidentally did. Same shape lives on unfixed in `EMAIL_BODY_LRU`, whose key embeds `last_accessed_at` — which is *why* `remove_body_cache` still scans that whole table. → [storage.rs](../../src-tauri/src/commands/email/storage.rs) `stored_order_key`
- **Prefix-scanning a `{a}::{b}::{c}` keyspace: only the *fully-qualified* prefix is safe — deriving a prefix by cutting at the first separator silently drops rows.** Email account ids are `{provider}:{email}` or `custom:{email}:{imap_host}`, and a custom account on an IPv6 literal host mints `custom:me@x.com:[::1]` — an id that **contains the separator**. A scan that found account blocks by cutting each key at the first `::` computed `custom:me@x.com:[::` and matched nothing, so that account's mail vanished from "All accounts" while still appearing when the account was selected: asymmetric and silent. Rule: scan a prefix you were *handed* (`Some(account_id)`), never one you *parsed out of a key*, and always keep the row's own fields as the inclusion test so the key can only ever narrow what you read, never decide what counts. → [storage.rs](../../src-tauri/src/commands/email/storage.rs) `list_envelopes_in_store`
- **Batching a per-row write into a per-chunk transaction silently multiplies the blast radius of a swallowed error — check what advances a cursor afterwards.** The IDLE worker did `let _ = upsert_envelope(...)` per row and then set `cursor.last_seen_uid = latest_uid`; with a 50-row batched write, one failure went from costing 1 message to costing 50 — and because the delta sync starts *after* the cursor and never looks back, those UIDs were stranded forever. Any `let _ =` write that a cursor/watermark update follows needs its result threaded into that update. → [realtime.rs](../../src-tauri/src/commands/email/realtime.rs)
- **`bun run verify` covers ZERO Rust, and a default `cargo check` skips the `lite` feature — a Rust-only block needs `cargo check` + `cargo check --features lite` + `cargo test --lib` as its own gate.** Also worth knowing when touching `src-tauri`: the crate is **not** `cargo fmt`-clean at baseline (~55 pre-existing hunks across untouched files) and CI runs no fmt check, so `cargo fmt` on a whole file buries the review diff — hand-apply rustfmt's output to your own hunks instead and leave the rest. (Restates the CLEAN-1 rule with the fmt trap; IM-2a, 2026-07-29.)
