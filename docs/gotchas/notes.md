# Gotchas: Lexical, notes, Notion import

Read before working in `src/features/notes/`, Lexical surfaces, import. Index of all areas: [docs/gotchas.md](../gotchas.md). Each entry: the trap, why it happens, what to do instead. A trap that bites twice should become a hook, a lint rule or a test.

## Lexical / spine text surfaces

- **A portal rendered next to a Lexical editor can't win focus with `autoFocus` — Lexical's post-update focus restore steals it back.** The slash menu's stage-2 picker mounted a cmdk `CommandInput` with autoFocus, but the `editor.update()` that removed the slash token re-focused the contenteditable a beat later → every keystroke went into the NOTE BODY while the picker sat mouse-only (cmdk only handles keys when focus is inside it). Focus such surfaces in a `setTimeout(≈30ms)` AFTER the update settles, and own your dismissal: Escape via the portal's own `onKeyDown` (the editor's `KEY_ESCAPE_COMMAND` only fires while the EDITOR has focus) plus a document-level `pointerdown` outside-check. → [slash-menu-plugin.tsx](../../src/features/notes/editor/plugins/slash-menu-plugin.tsx)
- **`@lexical/markdown`'s `ELEMENT_TRANSFORMERS` does NOT include `CHECK_LIST`** — spread the defaults and `- [x]` imports as a bullet item with LITERAL "[x]" text, and a byte-stable round-trip test still passes (export re-emits the literal). Add `CHECK_LIST` explicitly BEFORE the list transformers, and pin the STRUCTURE in tests (`"listType":"check"`, no literal marker), not just the bytes. Also: 0.40 ships no HR transformer (`---` needs a custom one), and ordered-list start lives on the LIST node's `start` field, not the items' `value`. → [markdown.ts](../../src/features/notes/editor/markdown.ts)

- **React portals into Lexical-owned DOM crash AND loop — Lexical's mutation observer reclaims foreign DOM inside its root.** NO-5's first task-line cut rendered checkbox/meta as portals into spans created in the node's `createDOM`: Lexical clawed the React children back out (empty spans), React's later unmount threw `NotFoundError: removeChild` (crashed the route boundary), and re-adding hosts from an update listener made Lexical's observer + the listener ping-pong into a main-thread-pegging infinite loop (evals timing out = the tell). **Never render React into elements Lexical created.** Chrome around editable lines goes in an absolutely-positioned OVERLAY div appended NEXT TO the contenteditable (inside the scroll container — abs-positioned content scrolls with it), geometry re-measured in the update listener + a ResizeObserver, element identity part of the re-render diff (the collab binding can recreate a node's DOM at any time). → [task-line-plugin.tsx](../../src/features/notes/editor/plugins/task-line-plugin.tsx)
- **`$getNearestNodeFromDOMNode` needs `editor.read`, not `editorState.read`.** It resolves the per-editor `__lexicalKey_<editorKey>` DOM property, which requires the ACTIVE editor binding — `editor.getEditorState().read(...)` has no editor bound and silently returns null for every element. Symptom: DOM→node lookups (hover affordances, context menus) dead with zero errors. → [task-line-plugin.tsx](../../src/features/notes/editor/plugins/task-line-plugin.tsx) `getNearestNodeKey`
- **Removing a Lexical list's last item self-destructs the LIST — insert replacements while the list is still attached.** `item.remove()` on the only `ListItemNode` removes the parent `ListNode` too; a following `list.insertAfter(x)` throws "Expected node N to have a parent" and the WHOLE update rolls back silently (the gesture just does nothing; the error only surfaces via the editor's onError). Insert first, remove second. → [task-line-plugin.tsx](../../src/features/notes/editor/plugins/task-line-plugin.tsx) `$convertItemToPendingLine`
- **`registerRootListener`: define DOM handlers OUTSIDE the callback.** Defining them inside makes `prevRoot?.removeEventListener(fn)` a no-op (fresh identity per call) and every effect re-run stacks another live listener on the same root (double-firing gestures). Define per effect run, attach/detach in the callback, and remove from `editor.getRootElement()` in the effect cleanup. → [task-line-plugin.tsx](../../src/features/notes/editor/plugins/task-line-plugin.tsx)
- **A bridge/context object that reads live data through refs must still CHANGE IDENTITY when that data changes.** `useNotesTaskBridge` reads tasks via `stable.current` (fresh on call), but consumers' effects/renders key on the bridge object — with a static identity the editor plugin never re-rendered on a tasks-bundle refresh (a checked task stayed visually unchecked; caught live). Include the data map in the memo deps even though the body doesn't close over it. → [use-notes-task-bridge.ts](../../src/features/notes/hooks/use-notes-task-bridge.ts)

## Lexical / spine text surfaces (cont.)

- **A new Lexical `DecoratorNode` must be added to the editor's `initialConfig.nodes` array or it throws on import/insert.** `EntityRefNode` is registered in [`LexicalNoteEditor.tsx`](../../src/features/notes/editor/LexicalNoteEditor.tsx); any future editor (comments in CT-5, etc.) that renders entity-ref chips must register it too. Inline decorator chips also need `createDOM` to set `contentEditable="false"` (mirror `EmbedNode`) or the caret lands *inside* the chip. → [src/features/spine/editor/entity-ref-node.tsx](../../src/features/spine/editor/entity-ref-node.tsx)
- **Keyboard handlers registered via `editor.registerCommand` capture a stale closure.** The handler is registered once (deps `[editor]`), so it sees first-render values of props/state. Route the action through a ref refreshed each render (`commitRef.current`) — the `@` MentionMenuPlugin does this for Enter; the legacy SlashCommandPlugin sidesteps it by fetching `getRuntime()` fresh inside each handler. A handler that reads `runtime`/`workspaceId` directly from the closure can use a null value that has since populated.
- **The `SlashCommand` union type is closed** ([`src/features/notes/types.ts`](../../src/features/notes/types.ts)) — adding a slash command id/group (e.g. the `/ref` "Refs" group) needs the union widened there or `tsc` rejects the `COMMANDS` entry. (`lint:tw` *ignores* the notes editor, so new menu UI there can match the legacy hex chrome — but spine files under `src/features/spine/` are gated and must be tokens-only.)
- **A Lexical `DecoratorNode` that must survive HTML serialization needs `exportDOM`/`importDOM` — `exportJSON`/`importJSON` is NOT enough (DF-23).** Notes persists via Yjs editor-state JSON, so `EntityRefNode` round-tripped for two waves with only JSON conversion. The moment it rides an **HTML**-persisted surface (email compose's `$generateHtmlFromNodes`, or the task/event `description` stored as HTML), a node without `exportDOM` serializes to an empty `<span>` and its entity address is lost. `EntityRefNode` now emits `<span data-lexical-entity-ref data-entity-*>Label</span>` and re-imports via `importDOM` (dropping a marker that's missing its address back to plain text). → [entity-ref-node.tsx](../../src/features/spine/editor/entity-ref-node.tsx)
- **Storing our rich HTML in a `description` column shared with untrusted/plain-text producers → NEVER `dangerouslySetInnerHTML`; use a shape heuristic + a DOM-walker renderer (DF-23).** Task/event `description` is one text column written by BOTH our editor (HTML with chips) AND external sync (Google/Graph/ICS plain text, possibly containing literal `<…>`). `looksLikeRichHtml` (`entity-rich-html.ts`) decides parse-vs-verbatim, and it must key ONLY on block tags our editor actually emits AND that the read-walker preserves *whole* — `pre`/`br` were dropped from the prefix so a matched string never renders half-flattened. `EntityRichText` (`entity-rich-text.tsx`) renders via `DOMParser` (inert) + an allowlist walk emitting only text/`<br>`/list-para/chip-spans (a `DROP` set kills script/style/iframe; unknown tags flatten to text, attrs dropped) — safe for untrusted mirror data without a sanitizer dependency. → [entity-rich-text.tsx](../../src/features/spine/ui/entity-rich-text.tsx)
- **A Lexical commit-on-blur must baseline against the SERIALIZED seed, not the raw stored string (DF-23).** A legacy plain-text `description` re-serializes to `<p><span style="white-space:pre-wrap">…</span></p>`, so baselining the "last committed" value off the raw string makes a bare focus→blur (no edit) look changed → a spurious write: an `updatedAt` bump, redundant reformat-sync, and (on the calendar RPC path) a phantom activity-trail row. Set the baseline from `serialize(editor)` in the plugin's mount effect (the seed plugin renders first, so the editor is already populated). → [entity-text-editor.tsx](../../src/features/spine/editor/entity-text-editor.tsx) `CommitOnBlurPlugin`
- **Generalizing a shared mention plugin for an insert-only surface: make `source` nullable and gate the `createLink` write on it (DF-23).** Email compose has no persistable source entity (an unsent draft), so `MentionMenuPlugin` accepts `source: EntityRef | null` and, when null, inserts the deep-linking chip but skips `executeMention` — otherwise it would `createLink` from an empty `{type:"",id:""}` ref. Also thread `triggerChar`/`trigger` so ONE plugin serves both `@`(mentions) and `/`(references); default them to `@`/`mention` so the Notes call site is unchanged. → [mention-menu-plugin.tsx](../../src/features/spine/editor/mention-menu-plugin.tsx)
- **Live-verifying a Lexical editor in the preview browser: synthetic mouse events don't work — focus via JS + a manual Range, select via a real bubbling `mousedown` (DF-23).** In the in-app preview tab, `computer.left_click` on a `contenteditable` leaves `document.activeElement === BODY` (the editor never focuses, so subsequent typed keys leak to global shortcuts and hijack the view). Instead: `el.focus()` + build a collapsed `Range` at the end, THEN `computer.type` (real keys reach the now-focused editor and drive Lexical's caret/mention detection). Menu-option selection via `computer.left_click` also no-ops (React 19's delegated `onMouseDown` doesn't fire); dispatch `new MouseEvent('mousedown',{bubbles:true})` on the option instead. And `computer.key "Return"` did NOT trigger Lexical's `KEY_ENTER_COMMAND`. Trust DOM/REST reads over screenshots.

- **Building an imported note's CRDT doc headless IS viable — `@lexical/headless` + `createBindingV2__EXPERIMENTAL` (NOTE-FIX-1, 2026-07-29, supersedes the NO-8 deferral).** The old shape (import writes `body_md` + EMPTY `doc_state`, a session-scoped in-memory map seeds the editor on first open) meant a note imported yesterday, or opened on another device, rendered **BLANK** — the worst dogfooding bug. `editor/materialize.ts` now builds the doc off-screen with the SAME node set (`editor/note-nodes.ts`, shared with the live editor — never let the two drift), the SAME `NOTES_TRANSFORMERS`, and the binding's default `root-v2` root; `editor.update(fn, {discrete:true})` is REQUIRED (a headless editor has no host to flush a deferred update, so without it the update listener never fires and the doc comes back empty), and `syncLexicalUpdateToYjsV2__EXPERIMENTAL` needs a provider carrying a real `Awareness` (it publishes the selection; a null one throws in `syncCursorPositions`). The importer now ships a real `docStateB64`; `SeedFromMarkdownPlugin`/`import-seed.ts` are **deleted**. → [materialize.ts](../../src/features/notes/editor/materialize.ts)
- **Two devices materializing the same blank note is a DUPLICATION risk, not a merge — the guard is server-side, not clever CRDT.** Merging two independently-built Yjs docs concatenates them (every block twice); it does not dedupe. `notes_op_seed_doc` is therefore ONCE-ONLY: it writes `doc_state` under the note's row lock and refuses if a snapshot exists **or any `note_updates` row does**. That second clause is essential — `doc_state` is only written by *compaction*, so a normally-created, edited note has a NULL snapshot with all its content in the log, and seeding it would duplicate everything. The deterministic `clientID` (FNV-1a of the note id) in `materialize.ts` is only defence-in-depth: it makes two same-bundle builds byte-identical, but different app versions serialize differently, so the server guard is the real guarantee. Residual known hole: a device holding an OLD-build in-editor seed it never pushed still looks empty server-side, so the sweep drains the local outbox (`engine.wake()`) BEFORE reading the work list, and skips entirely if that drain fails. → [repair.ts](../../src/features/notes/repair.ts)
- **(Resolved in NR-3) `deriveBody` was lossy.** The doc-text walker dropped link URLs, inline marks, in-block line breaks and tables, so `body_md` degraded on every edit. It is deleted; `editor/doc-markdown.ts` derives bodies through the real binding and `NOTES_TRANSFORMERS`. The import and the repair sweep still store the raw file until the first edit (a re-serialization normalizes markers and spacing). → [doc-markdown.ts](../../src/features/notes/editor/doc-markdown.ts)
- **The v2 collab binding writes element properties `__`-prefixed, and only when they DIFFER from a default-constructed node.** So `heading` carries `__tag`, `listitem` carries `__checked`/`__value` — but an **ordered** list carries NO `__listType` at all (ListNode's own default is `"number"`), and an ordered list's first item carries no `__value` (default 1). `deriveBody` read the bare names (`tag`, `listType`, …) for two waves, so every heading exported as `###`, every checklist as plain bullets and every ordered list as bullets — silently, in `body_md`. Fixed in NOTE-FIX-1: read `__name ?? name`, and default an absent list type to **number**, unconditionally (a content-dependent "which shape is this doc?" probe misclassifies a doc whose only non-default node is the list itself). When asserting this shape in a test, build the attributes the binding ACTUALLY emits — adding a `__value` to an ordered list's first item makes the test pass against a doc the app never produces. → [doc-text.ts](../../src/features/notes/sync/doc-text.ts)

## Notes / publish + MCP connector (NO-9/NO-10)

- **Supabase Edge Functions CANNOT serve rendered HTML — a `GET` returning `text/html` is rewritten to `text/plain` by the platform** (anti-abuse; [docs: Functions → Development tips](https://supabase.com/docs/guides/functions/development-tips) "HTML not supported"). The body is delivered intact but the browser shows raw source, not a page. Confirmed on `notes-public`: HEAD reported `text/html`, GET was forced to `text/plain`; custom headers (`x-robots-tag`) DO pass through, only the content-type is rewritten. **Consequence: NO-9's "edge function renders the published page from body_md" (spec assumption 8) is not viable as-is.** HTML must come from **Supabase Storage** (a public bucket serves the content-type you upload with — not rewritten) or from a **client-rendered app route** (the SPA is served with a real content-type; the edge fn returns JSON the page renders). Edge functions returning JSON (`application/json`) are fine. Don't build an edge-fn HTML renderer for a public page. → [supabase/functions/notes-public/index.ts](../../supabase/functions/notes-public/index.ts)

- **Rendering user markdown on a PUBLIC page must escape raw HTML + scheme-allow-list links — `marked` does neither by default.** `body_md` is user-authored, and marked passes raw HTML tokens through and renders any `href` verbatim, so a note containing `<script>` or a `[x](../javascript:…)` link becomes stored XSS on the published page. The `notes-public` edge fn overrides the renderer: `html()` → `escapeHtml` (block + inline raw HTML both flow there), `link()`/`image()` → `safeHref` allow-lists **only** `http(s):`/`mailto:` (a `moduo://` chip or `javascript:`/`data:` degrades to a plain escaped label). `marked.parse()` is synchronous unless `async:true` (the `as string` cast is valid). Any future untrusted-markdown→HTML surface needs the same two overrides — a hand-rolled regex sanitizer is the wrong tool. → [supabase/functions/notes-public/index.ts](../../supabase/functions/notes-public/index.ts)
- **`notes_op_import` does NOT guard `parent_id` (no FK, no in-workspace check) — unlike `notes_op_create`.** Import inserts `parentId` blindly (migration `notes_op_import`), so a bad/foreign/nonexistent parent silently lands the row as an orphan (tree builders re-root unresolvable parents — never a leak, the row still carries the caller's `workspace_id`, but the note isn't where you asked). The MCP connector's `notes_create` therefore validates the parent itself before importing. Any caller of `notes_op_import` that accepts an external parent_id must guard it. → [supabase/functions/moduo-mcp/modules/notes.ts](../../supabase/functions/moduo-mcp/modules/notes.ts)
- **~~`body_md` is DERIVED from the CRDT — writing it directly (connector create/append/update) desyncs it from `doc_state`.~~ Fixed by NR-6 (2026-10-14):** the connector now writes real Yjs updates and derives `body_md` with the app's converter; see §Agent writes (NR-6). Never reintroduce a body-only write to a note that has a doc.
- **Every module has its own permission lane since PERM-1, and a key's scope key is the module id.** Notes was the first (`permissionKey:'notes'`, `scopes->>'notes'`); Contacts and Calendar rode the Tasks lane until PERM-1 and now check `contacts` / `calendar`, and Links checks the `spine` lane (Edit on any module). Don't point a module's api-key branch at another module's scope: a keyed agent write would then check the wrong one. The manifests' `permissionKey` names the lane and `src/lib/module-registry.test.ts` pins it. → [src/features/notes/ops-manifest.ts](../../src/features/notes/ops-manifest.ts)
- **Archiving a note TAKES IT OFFLINE — `notes_op_archive` clears `published_at`/`publish_token` across the whole archived subtree** (designer call 2026-07-04; migration `20260704120000_notes_archive_unpublishes.sql`, a CREATE-OR-REPLACE follow-up on NO-1 — apply AFTER `20260703120000`). So a published note that gets archived (directly, or by an ancestor being archived) has its public link revoked; the `notes-public` edge fn 404s it (resolves by the now-null token) and also carries a `.not("is_archived","is",true)` root guard as defense-in-depth. Client mirror: `useNotesModule.archiveNote` clears the subtree's `publishedAt`/`publishToken` optimistically and toasts "Archived — the public link was turned off." `isPublished` (publish.ts) also excludes archived. **Unarchive does NOT re-publish** (token is gone; re-publishing is explicit). → [src/features/notes/hooks/use-notes-module.ts](../../src/features/notes/hooks/use-notes-module.ts)
- **Creating a note OUTSIDE /notes and immediately deep-linking to it (`moduo:entity:open` → `/notes?id=`) races the page's cache-first paint + stale-id cleanup — the selection gets cleared.** `/notes` paints from the IndexedDB meta cache first (offline-first, NO-2/NO-3), which does NOT contain a note just created via a bare `notesV2.create` on another page (that page's write doesn't touch /notes' cache). So on mount the cached bundle lacks the new id, `loading` flips false, and NO-3's stale-`?id` guard (`if (!notes.some(n => n.id === selectedId)) select(null, true)`) clears the deep link before the Supabase refresh lands. Bit NO-7b's "New linked note" auto-open (live-verified: note created+linked, but /notes opened blank). Fixes: don't auto-navigate on a cross-page create (NO-7b creates the linked note in place and surfaces it in the rail); OR give /notes' stale-cleanup a grace window like the contacts page's 2s FX-1 timeout. Clicking an EXISTING (already-cached) note's deep link is fine — the race is specific to a just-created id. → [src/routes/pages/notes-page.tsx](../../src/routes/pages/notes-page.tsx)

## Notes editor baseline (DF-13)

- **Lexical's markdown-shortcut element transformers only run on TOP-LEVEL blocks — typing `- [ ]` can never become a checkbox.** `runElementTransformers` bails unless the anchor block's parent is root, so `- ` converts the paragraph to a bullet *first*, and once the caret sits inside the `ListItemNode` no element transformer will ever fire again on that line (upstream design, 0.40). The live checkbox gesture is `[] ` / `[x] ` at line start (the CHECK_LIST regexp's dash is optional) or /todo. Don't burn time "fixing" transformer order — order can't help; only the plain-paragraph path exists. → [markdown.ts](../../src/features/notes/editor/markdown.ts) · node_modules/@lexical/markdown `runElementTransformers`
- **A Lexical theme without `theme.text.*` classes renders format COMBINATIONS and strikethrough/underline invisibly.** A text node carries all format bits, but only ONE wins the element tag (bold→`<strong>` beats italic); the rest render solely via theme classes. With `text: { code }` only, ⌘B+⌘I showed just bold, and strikethrough applied with zero visual change (state flips, selection.hasFormat true — nothing on screen). Every editor needs the full `bold/italic/strikethrough/underline/underlineStrikethrough` class map. Caught live in DF-13; the ⌘B/⌘I keybindings themselves are Lexical-core (no plugin needed). → [note-editor.tsx](../../src/features/notes/ui/note-editor.tsx) `initialConfig.theme.text` · [global.css](../../src/global.css) `.notes-text-*`
- **react-markdown renders HTML comments as literal visible text (no rehype-raw), so `body_md`'s `<!-- moduo:task:<id> -->` stable-id comments LEAKED onto the public page.** Anything the markdown export embeds as an HTML comment will be user-visible on `/p/<token>`. Strip render-side (`stripTaskIdComments`) — stripping at export would break re-import losslessness. → [public-render.ts](../../src/features/notes/public-render.ts)
- **The preview_start sandbox cannot boot a server inside this worktree (`EPERM uv_cwd`)** — same class as the recorded preview/worktree footgun. Recipe that works: background `rsbuild dev` on a free port via Bash + drive with the Chrome MCP; screenshots need the window visible (CDP capture fails on a hidden window — verify via `read_page`/`javascript_tool`, and test `md:` breakpoints in a 390px same-origin IFRAME, whose media queries evaluate against the iframe viewport).

## Notion import (IM-1)

- **A real Notion export is a ZIP INSIDE A ZIP — a reader that only looks one level in imports ZERO notes, silently.** The download is `Export-<uuid>.zip` containing `Export-<uuid>-Part-1.zip` containing the files; large workspaces add `Part-2`, `Part-3`. The old reader filtered the top level to markdown, found none, and produced an empty plan with no error. Unwrap recursively (bounded — an unbounded unwrap over untrusted input is a zip-bomb path) and **drop the nested zip's own name from the path**, or every page becomes a child of a phantom "Part 1" and a multi-part export splits into unrelated trees. Note the depth bound limits *nesting only*: `unzipSync` still materializes every entry eagerly on the main thread, so a flat bomb is undefended. → [import-zip.ts](../../src/features/notes/import-zip.ts)
- **Deriving a database id from a file path is a silent-data-loss bug when the path is normalized.** Import ids are derived so a re-run is a no-op — but seeding on the *cleaned* path (extension + Notion's 32-hex suffix stripped, lowercased) gives two same-titled sibling pages the SAME id, and `notes_op_import` resolves a duplicate id by **skipping the row**: the second page vanishes and its children reparent under the first. Notion appends that hex to every file *precisely because* sibling titles are not unique, and a real export also contains pages whose name cleans to empty (they all collide with each other). Seed on **Notion's page id**, and have the id assigner *guarantee* distinctness across the plan rather than trusting the seed — a collision must never be resolvable by the server's skip path. → [import.ts](../../src/features/notes/import.ts) `assignImportIds`
- **"Strip the longest prefix common to every entry" makes your output a function of the whole input set — deadly when ids are derived from it.** It's the obvious way to remove an export wrapper and it works on one drop, but every path (and so every derived id) then depends on the *shallowest* file present: one new top-level teamspace, one page promoted to the root, or dropping Part-2 on its own re-keys all 350 notes, and the next import duplicates the workspace instead of no-oping. Match the wrapper by **pattern, per entry**. → [import-zip.ts](../../src/features/notes/import-zip.ts) `stripExportWrapper`
- **Pick the motion token by what you animate, not by how it feels.** `--motion-fade` stays non-zero (80ms) under reduced motion because it is for opacity/color; the `--motion-*` movement tokens are zeroed. A width/transform/position transition on `--motion-fade` keeps travelling for a user who asked it not to — and `bun run verify` won't catch it. → [tokens.css](../../src/styles/tokens.css) §motion · [progress.tsx](../../src/components/ui/progress.tsx)

## Lexical

- **Lexical 0.49 changed `DecoratorNode` to extend `LexicalNode` instead of `ElementNode` — inline-ness is now opt-in via `isInline()`.** Custom nodes that worked as blocks under 0.40 silently become *inline* under 0.49 unless they declare `isInline() { return false; }`, which makes markdown import wrap them in a paragraph (their `replace()` result lands nested) and export them as `""`. This bit `EmbedNode` (only node missing the override) on the 0.40→0.49 bump. Check every custom DecoratorNode after a Lexical upgrade.
- **`syncLexicalUpdateToYjsV2__EXPERIMENTAL` added a `dirtyLeaves` parameter in 0.49.** If the collab listener destructures the update payload (`dirtyElements`, `normalizedNodes`, …) without it, the call becomes a type error. Add `dirtyLeaves` to the destructure and pass it through.
- **Under 0.49, headless `node.exportJSON()` returns `children: []`** for built-in element nodes — children serialization moved into `$exportNodeToJSON` (what `editor.getEditorState().toJSON()` uses). Direct `exportJSON()` consumers must refill children from `getChildren()` (the app's `$nodeToMdJson` already does).
- **`entire`'s auto-generated OpenCode plugin (`.opencode/plugins/entire.ts`) must NOT be reformatted.** The CLI hashes it against what `entire enable` writes; any edit (e.g. `biome --write`) flips `entire doctor`/`entire status` to "OpenCode hooks OUT OF DATE". Fix: `entire enable --force --agent opencode` to regenerate, then exclude the file from linting (it's now `!.opencode/plugins` in `biome.json`).
- **`entire` repo Analytics can show 0 checkpoints for a repo that clearly has activity** — the Home/account view aggregates across repos, but repo-level Analytics counts only checkpoints *attributed to commits in that repo's post-merge history*. A checkpoint created before a merge lands shows as `commits (none on this branch)` and doesn't count until a new checkpoint is created against the merged history. If a repo's Analytics looks empty: make a small commit after the last merge and push — the fresh checkpoint syncs to origin on push and becomes attributable.
- **Dev builds and the signed desktop app must never share a keychain service.** macOS ties each keychain entry's access list to the app that created it. When `bun run dev:desktop` and the signed `.dmg` app both used `com.moduo.desktop.auth` (with fixed account names), the signed app prompted for the login keychain password on every read of an entry a dev build had written — one prompt per module tab. Debug builds now default to `com.moduo.desktop.dev.auth` ([config.rs](../../src-tauri/src/config.rs)); staging and prod share `com.moduo.desktop.auth` (same Developer ID, same designated requirement). Never point a differently-signed build at the release service. Anyone hit already: quit the app, `while security delete-generic-password -s com.moduo.desktop.auth >/dev/null 2>&1; do :; done`, sign in again (desktop-connected email/calendar accounts must be reconnected).

- **`public.profiles` billing columns are server-owned (2026-10-06).** `authenticated`/`anon` have column grants only on display_name, avatar_url, local_user_id, recovery_seed_hash, cloud_linked, updated_at. Writing `plan_tier`/`subscription_status` from a client now fails. Edge functions use the service role. To change a plan by hand, edit the Stripe subscription (the sync engine + trigger update the profile) or add the email to `public.founder_emails`.
- **The Sync Engine installer owns the `stripe-webhook`, `stripe-setup`, `stripe-worker` function slugs.** The repo no longer contains a `stripe-webhook`; deploying one would overwrite the engine's handler and silently stop all billing updates.
- **Don't add permissive "plan check" RLS policies — they OR with the role policies.** `paid_plan_required_to_invite` was permissive next to `workspace_invites_insert_admin`, so Free owners could invite. Plan/seat limits are RESTRICTIVE policies (`workspace_seat_cap` vs `workspace_seats_used`) against the workspace OWNER's plan.

## Notes refresh data (NR-1)

- **Re-rooting an `inherit` sub-note silently made it private.** `can_access` walks up while `share_mode = 'inherit'` and stops at a parentless note, where only its creator and direct grants count, and an inherit note has no grants of its own (`share_note_after` skips them). So setting `parent_id = NULL` on a shared sub-note hid it from everyone but its creator. **Fixed in NR-1 for every path:** `notes_op_file`, `notes_op_move` to root, the restore re-root and the purge re-root all call `notes__keep_access_on_reroot` first (it copies the walked ancestors' grants and creators, then sets `custom`). Any NEW path that re-roots a note must call it too. → [notes_refresh_organize.sql](../../supabase/migrations/20261013120000_notes_refresh_organize.sql)
- **The repo's migration bodies are not prod's.** `notes_op_duplicate` in prod carries a can-open check from `20261008130000_definer_reads_item_visibility.sql`, which lives only on `maciej`. A `CREATE OR REPLACE` copied from this branch's newest file would have silently removed it. Before replacing any function, read prod's `prosrc` (read-only `pg_get_functiondef` through the Supabase MCP) and rebuild from that. The NR-1 replica (`replica-setup.sql`) shows how to rehearse against prod's real bodies.
- **Backfills in a migration must not re-run.** A re-applied `UPDATE … SET in_inbox = true` pushes notes users filed back into the Inbox. Put the column add plus its backfill (and a new table plus its seed) in a first-run-only `DO` block keyed on the column or table not existing yet.

## Notes shell (NR-2)

- **A bare `<DndContext>` (no `sensors`) uses dnd-kit's default PointerSensor, which activates on pointer-DOWN and then swallows the click** (`stopPropagation` on the next `click`, capture phase). Rows that are both draggable and clickable select nothing. Give every harness (stories, tests) the shell's sensors: `PointerSensor` with `activationConstraint: { distance: 6 }`. Synthetic `.click()` still works, so a jsdom test won't catch it. → [notes-sidebar.stories.tsx](../../src/features/notes/shell/notes-sidebar.stories.tsx)
- **The editor's collab bootstrap writes an empty paragraph into a new doc, so "the doc changed" is not "the user typed".** Lazy drafts test `hasDraftContent(deriveBody(doc).text)`, and the engine keeps a draft's updates out of the push outbox entirely until `promoteDraft`. Any new "is this note empty?" check must read the text, not count updates. → [draft-note.ts](../../src/features/notes/draft-note.ts), [engine-v2.ts](../../src/features/notes/sync/engine-v2.ts)
- **A module-level "current syncer" slot breaks when a second `usePreferences()` mounts and unmounts** (Settings → Preferences): the cleanup clears the slot while `<PreferencesSync/>` is still mounted, and imperative writes stop syncing. Keep registrations in a stack and remove only your own. → [preferences.ts](../../src/lib/preferences.ts)
- **dnd-kit's `delta` includes the scroll of any scrollable ancestor, so `activatorEvent + delta` is NOT the release point in a scrolling sidebar** (the TL-2 trap again, this time in NR-2's round-2 fix). Track the pointer with a capture `pointermove` listener attached synchronously in `onDragStart` (not an effect, which misses early moves) and resolve the drop from it. The `LongTree` story records the last drop on `window.__lastDrop` to re-check a scroll-mid-drag. → [use-sidebar-drag.ts](../../src/features/notes/shell/use-sidebar-drag.ts)

## Notes editor core (NR-3)

- **Mounting the collab editor on an EMPTY doc writes into it.** `CollaborationPluginV2`'s mount path (our `SyncFromYjsPlugin` → `CLEAR_DIFF_VERSIONS` → `syncYjsStateToLexicalV2`) calls `$ensureEditorNotEmpty` when `root-v2` has no children, and that paragraph syncs into Yjs and pushes like typing. Withholding the provider's `sync` event is not enough. Mount from the cache only when the cached doc has content; otherwise wait for the first pull. → [note-editor.tsx](../../src/features/notes/ui/note-editor.tsx)
- **A test that writes raw `Y.XmlText` into `root-v2` is not a note.** The binding's shape is `paragraph` elements over text runs; the one converter reads docs through Lexical, so a hand-built doc in the wrong shape derives nothing (and used to pass against the old walker). Build docs with `buildDocStateFromMarkdown`, or append `Y.XmlElement("paragraph")` over a `Y.XmlText`. → [engine-drafts.test.ts](../../src/features/notes/sync/engine-drafts.test.ts)
- **`@lexical/markdown` 0.52 merges adjacent non-empty lines into one paragraph with a line break**, and drops blank lines after import. Element transformers still see each line on its own, so a line-based transformer (tables) builds across lines by looking at the previous sibling; two tables separated by a blank line still import as two (the empty paragraph sits between them until the end).
- **The exporter escapes backslashes**: `C:\new` in, `C:\\new` out, then stable. Assert idempotence after one round trip, not byte equality, for text containing `\`.

## Agent writes (NR-6)

- **Edge Functions can't import the app's notes editor directly.** App sources use extensionless relative imports and bare `lexical`/`yjs` specifiers; Deno resolves neither without sloppy imports and a long import map. The connector lazy-loads a prebuilt single-file bundle instead (`bun run build:notes-doc`, built with Lexical's `production` conditions, ~390 KB). Rebuild it whenever anything under `src/features/notes/editor/` (or the spine chip schema, or a bundled package) changes: `modules/notes.test.ts` "notes-doc bundle is current" fails until you do, and also fails on a hand edit (code hash). Loading it needs env access (lib0 reads `process.env`). (2026-10-14)
- **An update encoded against a state vector carries the doc's whole delete set.** `Y.encodeStateAsUpdate(doc, sv)` includes every deletion the doc holds, not just the ones since `sv`. Pushed as "the agent's" change, a deletion a client hadn't seen yet lands inside the agent's transaction and its Undo restores another person's deleted text. Push only the edit's own `update` events (`Y.mergeUpdates`). (2026-10-14)
- **`Y.UndoManager` knows "already undone" only in the session that undid it.** Two sessions tracking the same remote change each offer Undo, and the second restores replaced text twice. The agent Undo keeps one step and clears on any `"remote"` change. Its `undo()` also silently skips steps whose content is gone and pops the next one, so never keep more than one step. Tracked origins match by identity or by constructor: track a class (`AgentOrigin`), and add any new non-local origin to `isForeignOrigin`, or the engine and relay push it back as a local edit. (2026-10-14)
- **Never trust "who wrote this" from a public broadcast.** `notes:<id>` is public until NR-7; any subscriber can send bytes tagged as anything. An agent write is announced by a content-free cue (`{ origin: "api_key" }`) and clients pull, so the stored row (written by the server from `module_api_key_id()`) is the only source of "it was an agent". (2026-10-14)
- **A body-only note must be seeded through `notes_op_seed_doc`, never inside another write.** The deterministic seed is identical only within one bundle build, and the web app and `moduo-mcp` deploy separately; only the server's once-only guard prevents two different seeds under one client id. (2026-10-14)
- **A connector call whose RPC sits in a helper above the tools fails `api-keys.test.ts`.** The key-scope test reads tool bodies for `callOp(ctx, "…")`; a call in a shared helper counts as "preamble" and must not hit a key lane. Keep each `callOp` in the tool handler and have helpers return the arguments. Likewise a new function body may not mention `auth.uid()` directly where a key calls: use `perm_actor_id()` gated on `module_api_key_id() IS NULL`. (2026-10-14)
- **A column tier added to the front of a `selectFirstDeployedTier` list shifts every index.** `listMeta`'s `degraded: tier === 2` silently started flagging the working v2 tier when NR-6 prepended a tier; compare against `tiers.length - 1`. (2026-10-14)
