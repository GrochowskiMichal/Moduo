## Contract

These are the design-system rules every component must follow. The Stylelint config enforces a strict subset; the rest is reviewed in code review and by Claude during implementation.

### 1. Tokens are the only source of design values

Component code uses semantic tokens, not raw values. Concretely:

- **Color**: `bg-background`, `text-foreground`, `bg-primary`, `border-border`, `text-muted-foreground`. Never `bg-zinc-900`, never `bg-[#141414]`, never `text-white/60`.
- **Spacing**: `p-4`, `gap-2`, `mx-3`. Never `p-[13px]`, never `gap-[10px]`.
- **Radius**: `rounded-md`, `rounded-lg`, `rounded-full`. Never `rounded-[7px]`.
- **Font family**: `font-display`, `font-sans` (resolves to the user's body font), `font-mono`. Never `font-[Inter]`.
- **Font size**: `text-base`, `text-lg`, `text-2xl`. Never `text-[15px]`.
- **Motion duration**: use `--motion-fast`, `--motion-base`, `--motion-slow` via CSS or via Tailwind's arbitrary value `duration-[var(--motion-base)]`. Never `duration-200`.

Tokens are defined in [src/styles/tokens.css](./src/styles/tokens.css). The full token catalogue with rationale is in [.design/foundation/TOKENS.md](./.design/foundation/TOKENS.md).

### 2. Token edits are system edits

If a token doesn't quite work for your case, you don't add a CSS variable to your component. You either:

- **Use a different token** (most cases — the system is dense enough that the right token usually exists).
- **Compose with opacity / mix** (use `bg-primary/80`, `bg-foreground/10` for subtle variants — Tailwind supports this).
- **Adjust the token** in `tokens.css` if the value is wrong system-wide. This is a deliberate change with review.

Never invent a per-component token. The system stays small or it stops being a system.

### 3. Primitives wrap shadcn

The `src/components/ui/` folder is for shadcn primitives. When you need a Dialog, Dropdown, Popover, Command, Tabs, Tooltip, Sheet, Toast, Switch, Select, RadioGroup, Separator, Card, ScrollArea, Avatar, Badge, or ContextMenu — use the shadcn version.

If the primitive isn't installed yet, install it via the shadcn CLI (see Recipes below). Don't hand-author Radix wrappers; shadcn already did that work.

### 4. Storybook is the spec

Every primitive in `src/components/ui/` ships with a `<name>.stories.tsx`. The story covers:
- Default state
- All meaningful variants (size, intent, disabled, error)
- Hover, focus, active states (use Storybook controls)

Feature components (anything in `src/components/`, `src/features/`) are encouraged to have stories but not required.

### 5. Visual snapshots in CI

Playwright runs visual snapshot tests for every primitive's Storybook story. New primitives must add a snapshot test alongside the story. If a story changes intentionally, the snapshot is regenerated by the author (not Claude — humans approve visual diffs).

### 6. No new fonts outside the picker

The font roles are:
- **Display**: Pilat Extended (default), Geist Sans, Cal Sans, Fraunces.
- **Body**: Geist Sans (default), Inter, Source Serif Pro, Geist Mono.

If a feature wants a new font, it's a design-system change, not a feature change. Discuss before adding.

### 7. No new top-level routes without intent

The app is converging from 23 exploratory routes to 5–7. Don't add another `/foo` route as a tangent. If you're building a new surface, confirm with the user where it lives.

## Customization architecture

User preferences map to `data-*` attributes on `<html>`. The cascade does the work; no React re-render is needed to change appearance.

| Attribute | Values | Default |
| --- | --- | --- |
| `data-theme` | `dark`, `light` | `dark` |
| `data-shade` | `black`, `warm`, `cool`, `slate`, `plum`, `forest` | `black` |
| `data-accent` | `pink`, `violet`, `blue`, `green`, `amber`, `red`, `teal`, `mono` | `pink` |
| `data-density` | `comfortable`, `compact`, `dense` | `comfortable` |
| `data-radius` | `sharp`, `soft`, `round` | `soft` |
| `data-font-display` | `pilat`, `geist`, `cal`, `fraunces` | `pilat` |
| `data-font-body` | `geist`, `inter`, `serif`, `mono` | `geist` |
| `data-text-size` | `small`, `normal`, `large` | `normal` |

The Settings page is the UI for setting these. The values persist to Tauri-backed local storage and are applied on app launch before first paint.

A simple `useAppearance()` hook returns the current values and a setter for each. Pseudocode:

```ts
function setAccent(value: AccentName) {
  document.documentElement.setAttribute("data-accent", value);
  prefs.set("appearance.accent", value);
}
```

## Component layer

### Primitives (`src/components/ui/`)
shadcn-derived. One primitive per file. Each primitive:
- Forwards refs (`React.forwardRef`).
- Supports `className` for one-off composition (but only with token-based utilities).
- Uses `cn()` for class merging (the shadcn helper).
- Lives next to its `.stories.tsx`.

### App shell (`src/components/app/`)
The chrome of the app — top bar, three-pane shell, menus. Uses primitives to compose.

### Bespoke shared (`src/components/`)
Modals, switchers, menus that are app-specific but used across features.

### Feature components (`src/features/<feature>/`)
Per-feature UI. May compose primitives + bespoke shared components. The visual personality of a feature comes from its composition, not from new tokens.

### React Native shim (`src/tw/`)
`View`, `Text`, `Pressable`, `TextInput`, `ScrollView`, `Image`, `Modal`, `ActivityIndicator`. These exist for code ported from a React Native codebase. Leave them alone; don't migrate them as part of the redesign.

## Recipes

### Add a shadcn primitive

```bash
# Once shadcn is initialised in the repo:
bunx shadcn@latest add <component-name>
# e.g.
bunx shadcn@latest add dropdown-menu popover command
```

The component lands in `src/components/ui/`. Open it; replace any default `bg-zinc-*` / `text-zinc-*` classes with our token classes (`bg-popover`, `text-popover-foreground`, etc.). Add a story file alongside.

### Add a new feature page

1. Confirm with the user that the route should exist (see rule 7).
2. Create `src/routes/pages/<name>-page.tsx`.
3. Add the route to `src/router.tsx`.
4. Add the page to the top-nav set if appropriate (in `app-chrome-constants.ts`).
5. Use the three-pane shell from `src/components/app/feature-panels-shell.tsx`.
6. Compose using primitives. If you reach for a hex value, stop and check the token reference.

### Add a new bespoke component

1. Create the file in the right folder (per the Component Layer section above).
2. Use only token-based classes (`bg-card`, `text-foreground`, etc.).
3. If you need a behaviour shadcn provides (focus trap, dropdown logic, etc.), wrap the shadcn primitive instead.
4. Add a story if it's reusable enough to be in `src/components/ui/`.

### Add a new accent color

1. Add `--{name}-base / -hover / -active` to the raw palette section in `tokens.css`.
2. Add a `[data-accent="{name}"]` block in the accent variants section.
3. Add the choice to the Settings page accent picker.
4. Add the name to the `AccentName` type in the `useAppearance` hook.
5. Verify the choice in the design-review skill with Playwright (run the visual snapshots).

### Add a new font

1. Install the @fontsource package: `bun add @fontsource/<font>` (or the variable version).
2. Import the package's CSS in `src/global.css` (or wherever fonts are loaded).
3. Add `--font-{role}-{name}` to the typography section of `tokens.css`.
4. Add a `[data-font-{role}="{name}"]` rule that resolves `--font-{role}`.
5. Add the choice to the Settings page font picker.
6. Verify rendering across themes and across text sizes.

### Change a token system-wide

1. Edit `src/styles/tokens.css` only.
2. Run Storybook (`bun run storybook`); spot-check the stories that use the changed token.
3. Run Playwright snapshots (`bun run e2e`). Approve the visual diffs.
4. Update [.design/foundation/TOKENS.md](./.design/foundation/TOKENS.md) if the rationale or default changed.

## Concentric inner radius

When you nest a rounded element inside another rounded element, the child's
radius must equal **outer radius − distance from the edge** so the two curves
read as concentric instead of parallel arcs.

Formula:

```
inner-radius = max(outer-radius − padding, 0)
```

Worked examples:

- A widget card inside a `rounded-xl` (16 px) panel with `p-5` (20 px) padding
  is `rounded-none` — the parent's curve already meets the child's corner.
- A notification card inside a `rounded-2xl` (24 px) sheet with `p-4` (16 px)
  padding lands at `rounded-md` (≈ 8 px).
- A chip inside a `rounded-md` (8 px) row with `p-2` (8 px) padding sits at
  `rounded-none` for the same reason.
- A graph node inside a `rounded-lg` (12 px) right-rail card with `p-3`
  (12 px) padding is `rounded-none` and uses the parent's curve directly.

Apply this anywhere a nested element borrows the visual frame from a parent:
the widget cards in the WIDGETS sidebar, the notification cards inside the
right sheet, the member / invite cards inside the workspace settings dialog,
chip rows inside outer cards. If the formula produces a value that doesn't
exist in the radius scale, pick the nearest scale step that keeps the curves
visually concentric.

This rule does not change tokens; it constrains how component code composes
them. The Stylelint config can't enforce it — the design-review skill catches
regressions during the visual sweep.

## Typography roles (primary vs. secondary)

Two user-selectable families live in Settings → Appearance: a **display** font
and a **body** font. Components map to a *role*, never to a hardcoded family, so
the user's choice always flows through:

- **Primary = `font-display`** — structure & app chrome: headings, section /
  eyebrow labels, control labels, **buttons**, menu / select triggers, and
  titles (task titles, page titles, the capture title + description).
- **Secondary = body** (the default; use `font-sans` to force it back where a
  primary ancestor would otherwise win) — content & context: dates, counters,
  row meta / badges, contextual descriptions, the capture-modal footer.

Rules:
- **Buttons are always primary.** The `Button` primitive sets `font-display` in
  its base — never body, never mono.
- `font-mono` is **code only** (it's also a selectable *body* alternate, but UI
  chrome must not depend on the body font being mono — that's why chrome uses
  `font-display`).
- Eyebrow / section labels use **`text-2xs`** (a token that scales with the
  Appearance → text-size setting).

## Casing

**Sentence case** across the UI. Saved here as the single convention for all new
copy:

- Buttons, labels, menu items, headings: "New task", "Do last", "Group",
  "Mark done", "Add description".
- Standalone status words and proper nouns stay capitalized: "Done", "Today",
  "Inbox", "Skip".
- Counts read like "2 / 2 Done".
- Acronyms and proper nouns as-is (CRM, Inbox).

## Stylelint enforcement (to be added)

A Stylelint config will land alongside the redesign work. It enforces:

- `declaration-property-value-disallowed-list` — no `color: #xxx`, `background: #xxx`, `border-color: #xxx` etc. outside `tokens.css`.
- `selector-class-pattern` — bans `bg-\[#`, `p-\[\d+px\]`, `text-\[\d+px\]`, `rounded-\[\d+px\]`, `font-\[` in className strings (via a custom rule or a regex check in CI).
- `unit-disallowed-list` — `px` for spacing/radius/typography (rem is allowed). `px` is OK for hairlines (1px borders).
- `font-family-no-missing-generic-family-keyword` — every font stack must end in a generic family.

Until the config lands, the rules are honour-system. Claude reads them; humans review them.
